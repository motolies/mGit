# 다국어 지원 구현 결과

작성일: 2026-11-20. mGit 의 화면을 한국어·영어 두 언어로 쓸 수 있게 한 작업(슬라이스 L1~L5)의 결과다. 계획:
`~/.claude/plans/serene-munching-comet.md`. 명세 반영: `claudedocs/mgit-기능-명세.md` UX-06·2.5·7.1·**11절**(i18n 계약). 사용자
문서 반영: `docs/사용법/8-설정.md` **8.11 언어**, 그리고 "외부 앱 설정" 이름을 쓰던 3·5·9·10장과 목차, README.

이 문서의 핵심은 **7절(알려진 한계)과 8절(실기기 확인 목록)** 이다. 앱은 자동 테스트와 목 모드 화면(영어·한국어 스크린샷 약 110장)으로
확인했다. 실제 앱(WKWebView·실제 OS 로캘·실제 IPC)은 상위 세션이 띄워 본 결과만 6절에 있다.

## 1. 요약

전에는 화면 문구가 한국어 한 벌(`packages/ui/src/strings.ts`)뿐이었고, 명세 UX-06 이 "다국어 프레임워크는 도입하지 않는다"로
정해 두었다. 지금은 **외부 라이브러리 없이 언어별 사전을 두고**, 화면은 지금처럼 `S.x.y(…)` 로 읽되 `S` 가 지금 언어의 사전을
가리킨다(ESM 라이브 바인딩). 한국어 사전의 모양이 기준 타입이라 영어 사전에 키가 빠지거나 함수 인자가 다르면 컴파일이 안 된다.
Rust 코어가 만드는 화면 문구(오류, 일괄 작업 라벨·건너뜀 사유, 충돌 편집기 열 제목, `.gitignore` 템플릿 이름, stash 메시지 등)도
새 크레이트 `mgit-l10n` 의 `pick`·`tr!` 로 두 언어를 함께 적고, 프로세스 전역 언어로 고른다.

언어는 처음에 **시스템 언어를 따른다**: macOS 선호 언어 목록의 첫 항목이 한국어면 한국어, 그 밖이나 읽지 못하면(1초 제한) 영어.
`⌘,` 대화상자를 "외부 앱 설정"에서 **설정**으로 넓혀 맨 위에 **언어 (Language)** 를 두었고, 저장하면 루트를 다시 마운트해 화면
전체가 즉시 새 언어로 다시 그려진다.

## 4. 구조

```
packages/ui/src/
  i18n/ko.ts                 한국어 사전 ko (모양의 기준)
  i18n/en/workspace.ts       영어 사전 묶음 — Pick<Strings, …>
  i18n/en/repository.ts      〃
  i18n/en/tools.ts           〃 (settings·actions 등)
  i18n/en/index.ts           joinSections 로 합친 en: Strings
  i18n/language-names.ts     언어 이름 (원어, 두 사전 공용)
  strings.ts                 Strings = Widen<typeof ko>, export let S, setStringsLocale
  locale.ts                  지금 언어 (의존성 없음)
  format.ts                  언어별 Intl 포맷터, formatNumber, plural
apps/desktop/src/
  store/language.ts          선호 load·save, readSystemLocale(1초), resolveLanguage, applyLanguage
  store/app-store.ts         language·uiLocale·systemLocale, initLanguage·setLanguage
  main.tsx                   첫 렌더 전에 initLanguage
  Root.tsx                   <App key={uiLocale}> — 언어가 바뀌면 다시 마운트
  features/app/AppDialogs.tsx  SettingsDialog (언어 + 외부 앱)
crates/mgit-l10n/            Lang, 전역 AtomicU8, set·current, pick, tr!
crates/*/src/messages.rs     크레이트별 메시지 함수 (model·core·hosting·셸)
apps/desktop/src-tauri/src/commands_app.rs  system_locale (sys-locale), set_language
```

흐름:

```
시작   main.tsx → initLanguage → 선호(mgit.language, 기본 system)
         → system 이면 system_locale (1초, 실패·시간 초과 = null)
         → resolveLanguage (언어 부분이 ko 면 ko, 그 밖·null 은 en)
         → applyLanguage (S·포맷·<html lang>) → set_language (Rust) → bootstrap → 첫 렌더
전환   설정 저장 → 외부 앱 저장 → 대화상자 닫기 → (언어가 바뀌었으면) setLanguage
         → 선호 저장 → 같은 적용·Rust 알림 → uiLocale 갱신 = 루트 다시 마운트 → .gitignore 템플릿 이름 다시 받기
```

- 스토어(세션·commit 메시지·충돌 초안·에디터 탭 등)는 React 밖이라 다시 마운트해도 남는다. 사라지는 것은 컴포넌트 지역 상태와
  터미널 셸(PTY 수명 = 뷰 마운트)이다.
- 목 클라이언트의 `systemLocale` 은 `navigator.language`, `setLanguage` 는 아무것도 하지 않는다. null 클라이언트는 null·빈 구현.

## 5. 계약과 새 문구 추가 규칙

자세한 계약은 **명세 11절**에 있다: 11.1 프런트 사전과 새 문구 규칙, 11.2 Rust 문구, 11.3 언어 결정과 전환(셸 명령 포함), 11.4 테스트
안전망. 새 문구를 더하는 사람이 지킬 것만 추리면:

1. 프런트 문구는 `i18n/ko.ts` 와 영어 묶음 파일(`i18n/en/*.ts`)에 **같은 키로 함께** 넣는다. 새 최상위 섹션이면 영어 묶음의 `Pick`
   목록에도.
2. 화면 코드에 한글을 쓰지 않는다(가드 테스트). 개발자용 throw·console 은 영어.
3. **모듈 최상위에서 `S` 를 미리 읽지 않는다** — 쓰는 시점에 읽는다.
4. 수량은 `formatNumber`, 영어 단수·복수는 `plural`. 로캘을 박아 두지 않는다.
5. Git 용어는 원어, 영어 단추·메뉴는 sentence case, `…`·단축키 표기 그대로.
6. Rust 에서 화면에 나가는 문구는 `pick`(고정)·`tr!`(값 포함). thiserror 는 `messages.rs` 함수로. 로그·expect·테스트는 한국어 그대로.

| tracing 로그·expect·테스트 문구는 한국어             | 영어 화면에서도 로그 파일·패닉 메시지는 한국어                                                                                                                                               | 개발자용이라 받아들임                                                   |
| 팔레트에서 "언어"로 찾아도 **설정…** 이 안 나온다    | 팔레트는 이름과 동작 id(`app.settings`)로만 찾는다. 사용법 8.11 에 "설정"으로 찾으라고 적었다                                                                                                | 동작에 검색 낱말(언어·language) 붙이기                                  |

## 8. ★ 실기기 확인 목록

실제 앱(`pnpm dev` 또는 빌드한 `.app`, WKWebView)에서 해 본다. 합성 폴더로 띄우려면 저장소 루트에서
`bench/setup.sh folder 20 2000` 뒤 `pnpm tauri dev -- -- "$PWD/bench/repos/folder-20x2000"`(`docs/빌드-테스트.md`).

- [x] (상위 세션 확인) 저장된 선호가 없는 첫 실행에서 이 Mac(선호 언어 맨 위 한국어)이 한국어로 감지돼 한국어 화면으로 뜨는지
- [ ] 첫 화면이 눈에 띄게 늦어지지 않는지(OS 로캘 읽기, 최대 1초)
- [ ] `⌘,`·팔레트 **설정…** 이 **설정** 대화상자를 열고, 맨 위 **언어 (Language)** 가 **시스템 언어 따름**, 그 아래 외부 앱 칸이 전과 같은지
- [ ] **English** 로 저장하면 대화상자가 닫히고 화면 전체(툴바·도구 창·상태 바·팔레트·로그 날짜·숫자)가 즉시 영어로 다시 그려지는지
- [ ] 앱을 끄고 다시 켜도 영어가 유지되는지(`mgit.language`)
- [ ] 폴더 탭 일괄 Fetch·Pull 결과의 라벨·요약·건너뜀 사유가 영어인지(Rust 문구)
- [ ] 오류 문구가 영어인지(예: 이미 있는 이름으로 branch 만들기, 저장소가 아닌 폴더 열기)
- [ ] 저장소 설정의 `.gitignore` 템플릿 이름이 영어인지 — 언어를 바꾼 직후에도
- [ ] 충돌 편집기 열 제목(rebase 충돌)과 앱이 만든 stash 메시지가 영어인지
- [ ] 터미널을 연 채 설정을 열면 **언어를 바꾸면 화면을 다시 그리면서 열린 터미널이 새로 시작됩니다**(영어 화면이면 **Changing the language redraws the window and restarts open terminals**)가 보이고, 저장 뒤 터미널이 새 셸로 시작하는지. 검증 명령으로 연 터미널이 명령을 다시 실행하지 않는지
- [ ] 언어를 바꾸기 전에 떠 있던 알림·오류가 이전 언어로 남는 정도가 거슬리지 않는지
- [ ] **System default** 로 되돌리면 한국어로 돌아오는지(이 Mac 기준), 다시 켜도 그대로인지
- [ ] 영어 화면에서 글자 넘침·잘림이 없는지(툴바, 단추, 대화상자, 상태 바, 필터 바 — 실제 WKWebView 글꼴). 특히 창을 960~1060px 로 줄였을 때 툴바의 탭 이름, Project 트리 저장소 행의 변경 수(7절)
- [ ] 한국어 화면에서 충돌 영역 머리(제목 한 줄 + 아래 줄 단추)와 일괄 작업 결과 표(사유 한 줄)가 바뀐 모습이 괜찮은지(L5 에서 영어 넘침을 고치며 함께 바뀜)

(선택) macOS 선호 언어 맨 위를 English 로 바꾸고 앱을 다시 켜면 시스템 언어 따름이 영어로 정해지는지 — 확인한 뒤 되돌린다.

## 9. 개발·확인 방법

```bash
pnpm lint && pnpm typecheck && pnpm test                        # 사전 완전성·한글 가드 포함
cargo test --workspace                                          # l10n_en 포함
cargo clippy --all-targets -- -D warnings
pnpm gen:ipc                                                    # 셸 명령을 더했을 때 bindings.ts 다시 만들기
rg -n '"[^"]*[가-힣]' crates apps/desktop/src-tauri/src         # Rust 한글 잔여 — 테스트·로그·expect·check.rs 뿐이어야 한다
```

- 목 모드에서 영어 화면 보기: 목 클라이언트는 브라우저 언어를 시스템 언어로 쓴다(브라우저마다 다르다 — en-US 면 영어, L5 의 Playwright 브라우저는 ko-KR 이었다). 한국어로 보려면 설정에서
  **한국어** 를 고르거나 `localStorage['mgit.language']='ko'` 를 넣고 다시 읽는다. 매뉴얼 그림 스크립트(`bench/docs-shots.js`)는 이
  값을 `ko` 로 넣는다.
- 새 문구를 더한 뒤 영어 화면을 확인할 때는 목 모드에서 English 로 바꿔 본다.
