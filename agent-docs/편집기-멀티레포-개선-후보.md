기준: 2026-11-26 · 기준 커밋 `d4e59bf` · 브랜치 `feat/multirepo-editor-batch1`

상태: 2026-11-27 완료. 아래 후보(A~R, M)와 고쳐야 할 문제를 모두 구현했고 #30 만 범위 밖으로 남았습니다. 커밋·판단·측정·실기기 확인 목록은 [편집기·멀티 레포 개선 구현 결과](편집기-멀티레포-개선-구현-결과.md)에 있습니다. 1절과 4절의 "근거" 는 조사 당시(`d4e59bf`) 코드 기준입니다.

## 배경

mGit을 **간단한 편집기 + 멀티 레포 관리 도구**로 쓴다는 목적에 맞춰 무엇을 더하거나 고칠지 조사했습니다.

- 조사 방법: `mt-plan`이 코드와 문서를 읽기만 하고 판단했습니다(빌드·실행 없음).
- P0 근거는 상위 세션이 코드에서 다시 확인했습니다.
- 경로는 저장소 루트 기준입니다. 줄 번호는 기준 커밋 기준입니다.

## 핵심 결론

- **가장 큰 흐름 끊김:** 여러 저장소에 새 branch를 만들고 commit한 뒤 일괄 push하면, 모든 저장소가 "업스트림 없음"으로 건너뛰어집니다.
  - 일괄 branch 생성이 `--no-track`으로 만듭니다.
  - 일괄 push는 업스트림이 없으면 git을 실행하기 전에 건너뜁니다.
- **편집기 문제:** LF와 CRLF가 섞인 파일은 편집은 물론 내용도 보이지 않습니다.
- **그 밖의 빈 곳:**
  - 폴더 탭 일괄 작업에 취소, 실패만 다시 시도, stash, 동기화 단축키가 없습니다.
  - 편집기에 괄호 짝, 자동 닫기, 접기, 다중 커서, 탭 복원이 없습니다.

## 5. 확인하지 못한 것

- 앱을 실행·빌드·측정하지 않았습니다. 판단은 모두 코드를 읽고 내렸습니다.
- 다음 두 비용은 측정하지 않았습니다.
  - 2초 주기 파일 검사(N7)
  - 입력할 때마다 도는 Blame 조회(N6)
- ⌘P가 입력마다 전체 폴더를 순회하는 비용도 측정하지 않았습니다.
- #7·#11 문구가 화면에 실제로 어떻게 보이는지 확인하지 않았습니다.

N6·N7 비용은 이후 `5913f2f` 에서 측정했습니다. 표는 결과 문서의 [N6 측정](편집기-멀티레포-개선-구현-결과.md#n6-측정)에 있습니다.
