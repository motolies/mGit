# IntelliJ식 화면 개편 구현 결과

작성일: 2026-11-20. mGit 의 화면을 IntelliJ IDEA 와 거의 같은 배치로 바꾼 개편(슬라이스 W0~W30)의 결과다. 계획:
`~/.claude/plans/ui-ux-glowing-walrus.md`(1~10절 설계, 부록 = 슬라이스마다 확정한 것). 명세 반영: `claudedocs/mgit-기능-명세.md`
3.2·3.16·7.1·10절. 앞선 결과 문서는 `claudedocs/phase3-g1-g2-구현-결과.md`.

개편 중에는 "판단이 나와도 멈추지 않고 끝에 모아 확인"하기로 했다(2절). 그래서 이 문서의 핵심은 **5절(판단·받아들인 동작)과
6절(실기기 확인 목록)** 이다. 5절의 항목 번호(A1, C3 …)로 바꿀 것을 알려 주면 된다.

## 1. 요약

폴더(여러 저장소)를 열면 전에는 대시보드 표 하나가 화면을 다 차지했고, 통합 타임라인에서 커밋을 고르면 저장소 탭으로 넘어갔다.
지금은 IntelliJ 처럼 **위 = 왼쪽 도구 창(Project·Commit·Pull Requests) + 가운데 에디터 공간, 아래 = Git 도구 창(브랜치 트리 | 로그 |
변경 파일·커밋 상세)** 이다. 커밋을 고르면 같은 창 오른쪽에 변경 파일과 상세가 뜨고, 파일을 누르면 에디터 탭에 diff 가 열린다.
옛 대시보드 표는 에디터의 "개요" 탭이 됐다. Project 트리는 폴더 전체의 파일 트리이고, 파일을 누르면 내용이 에디터 탭에 열린다.

단일 저장소 탭도 같은 틀이다. 옛 3단 레이아웃(사이드바 | 그래프 | 상세)과 사이드바는 없어졌고, 사이드바의 섹션은 브랜치 트리
(ref·워크트리·백업), Commit 도구 창의 Stash 탭(스태시), Pull Requests 도구 창(PR), Project 트리(모듈·서브모듈·하위 저장소·상위 저장소
링크)로 옮겨 갔다(4절). diff·충돌 화면은 에디터 탭이 됐고, 진행 중 작업 배너는 툴바 아래의 작업 진행 띠가 됐다.

폴더 화면에서 쓰기도 된다: 작업 트리 diff(hunk·줄 stage), 체크로 stage 하는 Commit 도구 창, 충돌 편집기, Continue·Skip·Abort.
이를 위해 저장소 세션을 탭 없이 가볍게 여는 "가벼운 세션"(폴더당 3개)을 더했다. 로그 필터 바(텍스트·해시·작성자·날짜·branch·
저장소)가 옛 저장소 간 검색 화면을 대체했다.

### 5.1 정해 줘야 할 판단 (C, 14)

- **C1** 폴더 Commit 도구 창의 체크는 **git index 를 그대로 비춘다** — 체크 = stage, 해제 = unstage, 일부만 stage 된 파일·폴더·저장소는 중간, 커밋은 stage 된 것만. IntelliJ 기본 모드(체크가 index 를 건드리지 않고 커밋 때만 반영)와 화면은 같고 뜻이 다르다. 사용자 확인(2.3)의 "체크한 파일만 커밋, 코어 일괄 커밋이 저장소별 경로 목록을 받게"와 구현 경로가 다르다(결과는 체크한 파일만 커밋된다). 왜: 저장소 탭이 index 기준이라 한 모델로 합치고, 작업 트리 diff 탭의 hunk·줄 stage 가 뜻을 갖고, 앱을 껐다 켜도·CLI 에서도 같은 상태. 바꾸려면: 코어의 일괄 커밋이 저장소별 경로 목록을 받게 한다. (W14)
- **C2** 툴바 일괄 작업의 "고른 저장소" = Project 트리에서 고른 **저장소 행 자체**. 저장소 안의 파일만 고른 채 Fetch·Pull 을 누르면 전체가 대상이다(툴팁에 수, Push 는 늘 확인창). 왜: 결정 10번의 글자 그대로, 사용자 확인에서 "Fetch·Pull 은 지금 규칙 그대로". 바꾸려면: "고른 행이 속한 가장 안쪽 저장소"로 넓히려면 `selectedRepoPaths` 한 곳. (W12)
- **C3** 활성 저장소가 에디터 탭과 트리 커서를 따른다 — 커밋 diff 탭이 열리면 그 저장소로, Project 트리에서 ↑↓ 로 행을 지나갈 때마다 바뀐다(바뀌는 것만으로 세션은 열지 않는다). 왜: IntelliJ 도 현재 저장소가 활성 에디터를 따른다. (W11)
- **C4** 충돌 수 0 → 양수에서 Commit 도구 창 자동 활성화(결정 15번)는 **저장소 탭만**. 폴더 탭은 띠의 충돌 수·"충돌 해결"로 연다. (W21 ②)
- **C5** Git 도구 창이 좁을 때: 폭 760px 미만이면 브랜치 트리를 접는 규칙은 최소 창(960×600 → Git 도구 창 924px)에서는 발동하지 않는다. WS-06 의 620px 규칙(변경·상세 자동 접힘)은 만들지 않았다. 왜: 세 칸 최소 폭 합(160 + 360 + 220)이 924 안에 들어간다. (W3)
- **C6** 폴더 로그의 다중·범위 선택(LG-07 의 ⌘·⇧)을 만들지 않았다. 왜: 여러 커밋의 합친 변경을 주는 폴더 API 가 없다(CD-08 과 함께 후속). (W8)
- **C7** 포함 브랜치의 "마지막 요청만 살리기" 열쇠가 요청을 받은 세션이라, 폴더는 저장소별이 아니라 폴더 하나다(다른 저장소의 커밋으로 옮겨도 앞 요청을 취소). 왜: 프런트 로더가 폴더당 하나이고 통합 타임라인은 이웃 행의 저장소가 자주 바뀐다. 바꾸려면: 열쇠를 `(SessionId, PathBuf)` 로. (W18 ①)
- **C8** 폴더 콘솔에 넣지 않은 것: "실패만 보기"(좁혀 보기는 저장소 칩만), 알림을 눌러 콘솔로 가기. 왜: 알림 → 콘솔은 토스트가 통째로 닫기 단추라 `components/Toasts.tsx` 구조를 바꿔야 한다. (W19 ②)
- **C9** 저장소 탭 Commit 도구 창(변경 탭)에는 폴더 모드의 분할선(`CommitToolSplit`)을 싣지 않았다 — 변경 목록 최소 5줄 + 바깥 스크롤. 왜: 커밋 폼이 193px 고정이라 분할 아래 칸(기본 약 142px·최소 104px)에서 잘리고, 저장 키 `commit-tool` 을 폴더와 공유하는 문제도 남는다. (W21 ①, W23)
- **C10** 저장소 탭에서 ⌘0 이 변경 목록의 첫 항목에 닿는다 — 트리 보기면 첫 디렉터리 단추("▾ docs"). (W27)
- **C11** PR 목록 배지의 경계선(대비 1.27 / 1.23)은 조작 요소가 아니고 뜻을 글자로 전하므로 대비 기준(WCAG 1.4.11) 대상이 아니라고 봤다. 다크에서 경계선이 거의 안 보인다. (W24, W27)
- **C12** 저장소 탭에서 필터 질의를 바꾼 직후 "읽는 중" 표시가 없다 — 응답 뒤 그림자 재로드라 그 전까지 상태 글자가 옛 행 수이고, "필터 지우기" 직후 잠깐 "commit 이 없습니다"가 번쩍일 수 있다(옛 화면도 같다). 바꾸려면: 세션 스토어가 요청 시점에 `reloading` 을 세운다. (W26)
- **C13** 1400 폭 한 줄 필터 바에서 조건 2개 + 목록 모드 + 찾기면 걸린 조건 단추가 말줄임된다. (W26)
- **C14** 저장소 탭 목록 모드에서 범위 선택의 행 수는 걸러진 행을 세는데 diff 는 두 커밋 사이 전체다(코드 추론). (W26)

### 5.2 적용하지 않은 UX 권고 (D, 7)

D1~D5 는 옛 라벨·표시 조건을 지키느라 적용하지 않았다.

- **D1** 서브모듈 메뉴의 "열기" → "저장소 탭으로 열기", 제거를 맨 끝으로. (W25)
- **D2** 모듈·서브모듈이 0개여도 ⋮ 와 "추가…"를 보이기 — 지금은 옛 조건대로 숨겨 **첫 서브모듈·모듈을 화면에서 추가할 길이 없다**(옛 것도 같았다). (W25)
- **D3** 미초기화 서브모듈의 "열기"를 끄기 — 열면 상위 저장소로 갈 가능성(미확인). (W25)
- **D4** Project 머리 ⋮ 메뉴에서 고른 뒤 포커스를 트리로(지금은 ⋮ 단추 — A65). (W25)
- **D5** 충돌 서브모듈이 있으면 ⋮ 에 표시. (W25)
- **D6** 작업 진행 띠의 줄(group)에 안내·상태 글자를 `aria-describedby` 로 — 지금은 꺼진 Continue 의 사유를 보조 기술이 모른다. (W27)
- **D7** 띠에 다시 들어올 때의 기본 포커스를 격리 줄이 아닌 첫 작업 줄로. (W27)

### 5.3 동작이 바뀐 것 (A, 80)

**화면 틀·도구 창·에디터 (A1~A13)**

- **A1** 저장소 탭에서도 Git 도구 창이 기본으로 보여 위 영역이 55% 로 줄었다(960×600 에서 294px). (W21 ①)
- **A2** 도구 창 상태가 앱 전역 1벌이다 — 저장소 탭에서 ⌘J(콘솔)를 누르거나 충돌로 Commit 이 자동으로 열리면 폴더 탭으로 가도 그렇게 보인다(아래 도구 창의 도구·Git 탭, 왼쪽 도구 창). 왜: 결정 4번(패널 크기·가시성은 앱 전역 1벌). (W3, W21 ②)
- **A3** 터미널 도구 창이 열린 채 앱을 끝냈으면 재시작 때 셸을 하나 자동으로 띄운다. 왜: IntelliJ 와 같은 동작. (W2)
- **A4** 에디터에 문서를 열면 아래 도구 창의 최대화가 풀린다. (W21 ①)
- **A5** 문서가 사라지면 직전 문서로 돌아간다(충돌 → 파일 diff → 닫기 → 충돌 탭). 옛 저장소 화면은 그래프로 돌아갔다. (W21 ①)
- **A6** "← 그래프로"·"← 목록으로" 단추가 없다 — 탭 닫기(×·Esc·⌘W). (W21 ①)
- **A7** 부모·자식 이동, 브랜치 트리 행 클릭, blame·출처 해시로 커밋으로 갈 때 에디터를 그대로 두고 Git 도구 창의 로그 탭을 연다. (W21 ①)
- **A8** ⌘1 = Project 도구 창, ⌘0 이 저장소 탭에서도 Commit 도구 창, ⇧Esc 뒤 포커스는 에디터. (W21 ①)
- **A9** 충돌 탭 닫기(×·편집기 밖 Esc)에 초안 확인이 붙었다(옛 저장소 탭에는 없었다). (W21 ①)
- **A10** 폴더 탭이 같은 세션의 충돌 탭을 닫을 때 저장소 탭이 diff 를 보던 중이면 diff 가 남는다(옛 화면은 그래프). (W20, 테스트·코드 분석으로 정함)
- **A11** 충돌 읽기가 실패했는데 그 사이 파일을 열었으면 diff 가 남는다(수 ms 경합). (W20)
- **A12** 충돌을 읽는 중에 Esc 를 누르면 읽는 중 문서가 남아 다 읽은 뒤 충돌을 보인다(수 ms 경합). (W20)
- **A13** 폴더가 충돌을 연 뒤 diff 를 열었다 닫은 세션을 저장소 탭으로 승격하면 충돌을 보인다(옛 화면은 그래프). (W20)

**폴더 탭·여러 탭 사이 (A14~A27)**

- **A14** Project 트리의 저장소 행(저장소 탭에서는 서브모듈·하위 저장소 행도) 더블클릭·Enter = **펼침**. 저장소 탭으로 열기는 우클릭 메뉴(저장소 탭에서는 행 메뉴 첫 항목). 옛 것은 더블클릭 = 탭으로 열기. (W11, W25)
- **A15** 저장소 밖의 항목(폴더 루트의 일반 파일 등)을 고르면 활성 저장소는 그대로다. (W11)
- **A16** 같은 저장소가 저장소 탭으로도 열려 있으면 한쪽에서 연 작업 트리 diff·충돌이 다른 쪽에도 탭으로 뜨고, 한쪽에서 닫으면 다른 쪽 것도 닫힌다. 왜: 세션 슬롯 하나 = 탭 하나. (W14 ②, W15)
- **A17** diff 탭으로 보던 파일의 마지막 작업 트리 변경을 stage 하거나 Commit 도구 창에서 그 파일을 체크하면 그 diff 탭이 닫힌다(세션 스토어의 기존 규칙). (W14 ②)
- **A18** 충돌을 열면 같은 저장소의 작업 트리 diff 탭이 닫힌다(기존 규칙). (W15)
- **A19** 폴더 탭에서 hook 실패 힌트는 안내만 한다(다시 시도 단추 없음). (W15)
- **A20** 세션의 commit 이 긴 일괄 fetch 뒤에서 표시 없이 기다릴 수 있다. 왜: 일괄 작업이 세션 쓰기 큐와 같은 쓰기 잠금을 잡는다. (W13 ②)
- **A21** 포함 브랜치가 시간 초과로 끝난 상태에서 ref 가 바뀌면 한 번 자동으로 다시 묻는다. (W9)
- **A22** checkout 확인창에서 이미 그 branch 가 현재인 저장소는 꺼진 칸이 아니라 체크할 수 있는 빈 칸이다. (W19 ①)
- **A23** Abort 뒤에도 "저장하지 않은 편집을 버렸습니다" 알림을 낸다(문구는 사유에 맞게 "작업을 중단해 …"). 바꾸려면: `pruneDrafts` 의 cause 분기 한 곳. (W19 ①)
- **A24** 같은 저장소를 연 저장소 탭의 쓰기(그 탭의 5분 자동 fetch 포함)가 폴더 콘솔에도 쌓일 수 있다(코드 추론). (W19 ②)
- **A25** 워크트리에서 돈 명령은 폴더 콘솔에 원 저장소 이름으로 보인다(칩 툴팁에 작업 디렉터리). (W19 ②)
- **A26** 폴더 콘솔 행에도 "쓰기" 칸이 남는다(폴더 콘솔은 늘 쓰기 명령이라 정보가 없다). (W19 ②)
- **A27** 띠의 "충돌 해결"(충돌 파일 여럿) 동작이 탭마다 다르다 — 저장소 탭 = Commit 도구 창을 열고 포커스(최대화 해제), 폴더 탭 = 왼쪽 도구 창만 Commit 으로 바꾸고 그 저장소를 펼친다. (W21 ②)

**로그 필터 바 (A28~A37)**

- **A28** 드롭다운은 "닫으면 적용"이고 Esc 도 닫기 = 적용이다(취소가 아니다). 바꾸려면: `FilterDropdown` 의 close 한 곳. (W17)
- **A29** 저장소 범위를 바꾸면 고른 커밋은 그 저장소가 범위에서 빠질 때만 비운다(필터 질의를 바꾸면 늘 비운다). (W17)
- **A30** 저장소 탭의 "모두 지우기"는 조건·경로만 지운다(정렬·첫 부모·머지 제외·원격 숨기기는 남김 — 폴더와 같게). 옛 전체 초기화 = 보기 옵션 "필터·옵션 초기화". (W26)
- **A31** branch 드롭다운에 현재 branch 행(solo — 그 이름에 고정, 옛 "main 만")과 HEAD(head — checkout 을 따라감)가 둘 다 있다. (W26)
- **A32** ⌘⇧G = 필터 텍스트 칸으로 포커스(옛 것은 필터 바 열기/닫기). (W26)
- **A33** 조건 요약 글자 대신 걸린 조건 단추와 보기 옵션의 점으로 보인다. (W26)
- **A34** 찾기 단추가 찾기 줄 열기/닫기 토글이다. (W26)
- **A35** 쓰기 중에는 텍스트·작성자·날짜까지 질의를 바꾸는 조작이 모두 잠긴다. (W26)
- **A36** 잘못된 정규식이 알림 대신 입력란 아래 안내로 뜨고 이전 결과가 남는다. (W26)
- **A37** 드롭다운을 닫은 뒤 코어 응답까지 단추가 옛 값이다(비낙관적 — 실기기 수십 ms 예상, 미측정). (W26)

**저장소 탭 브랜치 트리 (A38~A46)**

- **A38** 정렬이 이름순 → 현재 > 즐겨찾기 > 이름(원격 그룹 안도). (W22)

- **A40** `HEAD (현재 브랜치)` 행이 생겼다(클릭 = HEAD 커밋으로, 더블클릭·메뉴 없음). (W22)
- **A41** Space = 클릭(고르고 그 커밋으로), Enter = 더블클릭(checkout). (W22)
- **A42** 표기: `↑2 ↓12` → `⇣12 ⇡2`, 배지는 아이콘, 그룹 이름은 로컬·원격·태그·워크트리·백업. (W22)

- **A44** 원격 그룹 행 클릭 = 접기·펴기(옛 것은 동작 없음). (W22)
- **A45** 검색 칸이 생겼다(이름 부분 일치 — 원격 잎은 이름에 원격이 없어 "origin" 으로는 못 찾는다). (W22)

### 5.4 받아들인 위험·한계 (B, 49)

**보안·데이터 (B1~B11, 7절에 자세히)**

- **B1** 파일 API 가 "확인 뒤 바꿔치기"를 완전히 닫지 못한다(세 번 바꿔치기 경합). 사용자가 "지금은 둔다"로 정했다. 바꾸려면: `rustix` 의 `openat` 사슬로 unix 쪽 읽기·나열을 다시 쓴다(약 150줄, 직접 의존성 1개). (W10, 사용자 확인)
- **B2** unix 가 아닌 플랫폼은 링크를 따라가지 않는 열기와 파일 식별자 대조가 약하다(종류만 비교, 미검증). (W10)
- **B3** 이름이 `x.git` 인 bare 저장소 디렉터리는 평범한 디렉터리로 보이고 읽힌다(`.git` 이름만 막는다). (W10)
- **B4** 루트 안에 만든 하드 링크는 구분하지 못한다(만들려면 쓰기 권한이 필요). (W10)
- **B5** 이름이 255 바이트를 넘는 파일(한글 86자 이상)은 나열되지만 열 수 없다(`openable: false`). 왜: 상한을 올리면 W6 의 경로 계약이 바뀐다. (W10)
- **B6** 충돌 저장 경로만 고쳤고 `submodule.rs`·`conflict_assist.rs`·`modules.rs` 의 `work_tree.join` 은 점검하지 않았다. (W13 ①)
- **B7** clean·process 필터(`.gitattributes` 가 지정하고 명령은 사용자 git 설정에 있는 것 — git-lfs 등)는 가벼운 세션·폴더 요약의 status 에서도 돈다. 왜: 끄면 LFS 저장소가 전부 수정됨으로 보인다. fsmonitor 와 `post-index-change` 훅은 막았다. (W13 ②)

### 9.4 목의 한계

- 폴더 장면의 폴더 stage·unstage·commit 과 충돌 해결·Continue·Skip·Abort 는 상태를 바꾸지만 타임라인에 새 커밋이 생기지 않고 파일 트리는
  안 바뀐다. rebase 의 다음 단계가 없고(계속·건너뛰기가 바로 끝남), rerere·hook 은 흉내 내지 않는다.
- 일괄 작업은 결과(push 거부 등)를 돌려주지만 상태를 바꾸지 않는다. 저장소 탭의 checkout·삭제·stash 등은 인자까지만 받는다.
- 가벼운 세션의 이력은 타임라인과 다른 합성 데이터라 blame·히스토리 해시를 누른 뒤 로그 상세가 "unknown commit" 이다.
- 필터 정규식은 JS RegExp(ERE 와 세부가 다르고 본문 검색 없음). 저장소 탭 그래프는 첫 부모·머지 제외·원격 숨기기·경로·ref 범위로 거르지
  않고, 찾기(`searchCommits`)는 빈 스텁이다. 목 파일 시스템은 대소문자를 구분한다(실제 macOS 와 다름).
- 개발 모드는 `StrictMode` 라 문서를 열 때 읽기가 2번 찍힌다(배포본은 1번).
