# 10. 문제 해결

화면에 오류나 안내가 뜰 때 원인과 대처를 찾는 장입니다. 절마다 화면에 보이는 글자(증상) → 원인 → 해결 순서로 적었습니다. 여기 없는 오류는 [10.12](#1012-알-수-없는-오류를-알릴-때)처럼 Git 콘솔의 기록을 복사해 알려 주세요.

기준: 브랜치 `feat/tag-management` · 커밋 `aedc0b6` · 2026-11-23

오류가 보이는 자리는 셋입니다.

- 툴바 오른쪽의 빨간 칸: 저장소 열기·clone 같은 앱 수준 오류. 누르면 사라집니다.
- 툴바 아래(작업 진행 띠가 있으면 그 아래)의 빨간 오류 줄: 저장소에서 실행한 Git 작업의 오류(`git … 실패: <git 메시지>`). 누르면 사라지고, 길면 마우스를 올려 전체를 봅니다.
- 알림(오른쪽 아래의 토스트): 폴더 탭 일괄 작업의 결과처럼 여러 건을 모은 것.

## 10.1 git 이 없거나 버전이 낮을 때

### 증상

- 상태 바 오른쪽 끝에 git 버전 대신 **git 없음** 이 보입니다.
- 마우스를 올리면 이유가 보입니다: **git을 찾을 수 없습니다**, 또는 `git 2.39.5는 최소 버전 2.45.0 미만입니다` 꼴.
- 지난번에 열려 있던 탭을 다시 열지 않습니다.

### 원인

mGit 은 git 을 품고 있지 않고 Mac 에 설치된 git 을 씁니다. 앱을 켤 때 한 번 찾고, 버전이 2.45.0 보다 낮으면 쓰지 않습니다.

git 은 아래 순서로 찾습니다. 앱 안에서 git 경로를 정하는 설정은 없습니다([8.10](8-설정.md#810-바꿀-수-없는-값)).

1. 앱이 켜질 때 받은 PATH 의 폴더들
2. `/opt/homebrew/bin/git`
3. `/usr/local/bin/git`
4. `/usr/bin/git`

찾은 것이 `/usr/bin/git` 이면 Xcode(또는 Command Line Tools)에 든 실제 git 으로 바꿔 씁니다(`xcrun --find git` 이 알려 주는 경로).

> [!NOTE]
> Finder·Dock 으로 켠 앱이 받는 PATH 에는 보통 `/usr/bin` 같은 기본 폴더만 있습니다. 그래서 1단계에서 `/usr/bin/git` 이 먼저 잡혀 Command Line Tools 의 git 을 쓰고, Homebrew 로 설치한 git 은 쓰지 않을 수 있습니다(실제 Mac 에서 확인 전). 터미널의 `git --version` 과 상태 바의 버전이 다르면 이 경우입니다.
>
> 로그인 셸(터미널)의 PATH 는 git 을 찾을 때가 아니라, 찾은 git 과 hook·외부 앱을 실행할 때 붙습니다. 그래서 hook 이 부르는 `node` 같은 도구는 터미널과 같이 찾습니다.

### 해결

1. 앱이 쓰는 git 의 버전을 터미널에서 확인합니다.

   ```sh
   /usr/bin/git --version   # Finder 로 켠 앱이 보통 쓰는 git
   xcrun --find git         # 그 git 의 실제 경로
   git --version            # 터미널의 git (다를 수 있음)
   ```

2. `/usr/bin/git --version` 이 실패하거나 2.45 보다 낮으면 Command Line Tools 를 설치하거나 올립니다.
   - 설치: 터미널에서 `xcode-select --install`
   - 올리기: 시스템 설정 → 일반 → 소프트웨어 업데이트
3. Homebrew 의 git(`brew install git`)을 쓰고 싶어도, 위 NOTE 처럼 Finder 로 켠 앱은 그 git 을 쓰지 않을 수 있습니다. 상태 바의 버전으로 확인하세요.
4. 앱을 완전히 끝내고(`⌘Q`) 다시 켭니다. git 은 앱을 켤 때만 찾습니다.

## 10.2 index.lock 이 남아 있을 때

### 증상

대화상자 **index.lock 이 남아 있습니다** 가 뜹니다. 폴더 탭에서는 제목 앞에 저장소 이름이 붙습니다(`<저장소>: index.lock 이 남아 있습니다`).

- 본문: **다른 git 프로세스가 비정상 종료해 잠금 파일이 남았을 수 있습니다. 다른 git 명령이 돌고 있지 않다면 지워도 됩니다.**
- 단추: **취소**·**lock 파일 삭제**. 실수로 지우지 않게 처음 포커스는 **취소** 에 있습니다.

### 원인

git 은 stage 영역(index)을 고치는 동안 `.git/index.lock` 파일을 만들어 다른 git 이 동시에 고치지 못하게 막고, 끝나면 지웁니다. 다음 경우에 앱의 명령이 막힙니다.

- 터미널·에디터·다른 Git 앱의 git 명령이 지금 도는 중
- 앞서 돌던 git 이 비정상으로 끝나 잠금 파일이 남음

앱은 잠깐(약 1초) 다시 시도하고, 그래도 잠겨 있으면 이 대화상자를 띄웁니다.

### 해결

1. 다른 곳에서 git 이 도는지 봅니다. 터미널의 git 명령, 에디터의 Git 기능, 다른 Git 앱을 확인합니다.
2. 돌고 있으면 끝날 때까지 기다린 뒤 **취소** 를 누르고 같은 작업을 다시 합니다.
3. 도는 것이 없으면 **lock 파일 삭제** 를 누르고 같은 작업을 다시 합니다.

잠금 파일이 만들어진 지 1분이 안 됐으면 앱이 지우지 않습니다. 빨간 오류 줄에 `index.lock 이 방금 만들어졌습니다. 다른 git 명령이 끝나길 기다리세요` 가 보입니다. 1분쯤 기다렸다가 다시 합니다.

터미널에서 직접 지우려면, 다른 git 이 돌지 않는 것을 확인한 뒤 저장소 폴더에서 다음을 실행합니다.

```sh
cd ~/work/acme-platform/storefront-web
rm "$(git rev-parse --git-dir)/index.lock"
```

워크트리·서브모듈은 `.git` 이 폴더가 아니라 파일이라 잠금 파일이 다른 곳에 있습니다. `git rev-parse --git-dir` 이 그 자리를 알려 줍니다.

폴더 탭의 일괄 작업(Fetch·Pull·Push·commit, Commit 도구 창의 체크)에서는 이 대화상자가 뜨지 않습니다. 결과 알림에 그 저장소가 실패로 나오고 git 메시지에 `index.lock` 이 보입니다. 위 1번을 확인한 뒤 터미널에서 지우거나, 그 저장소를 저장소 탭으로 열어 다시 합니다.

| 보이는 것                                              | 원인                                                                    | 해결                                                                                                                                     |
| ------------------------------------------------------ | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 툴바 빨간 칸에 **Git 저장소가 아닙니다**: `<경로>`     | 고른 폴더가 저장소가 아니고, 바로 아래 폴더에도 저장소가 없음           | 저장소의 맨 위 폴더나, 저장소들이 바로 아래에 든 폴더를 고릅니다([2.1 폴더 탭이 되는 조건](2-저장소와-폴더-열기.md#폴더-탭이-되는-조건)) |
| `지원하지 않음: bare 저장소`                           | 작업 폴더가 없는 bare 저장소(서버에 두는 형태)                          | 열 수 없습니다. 터미널에서 `git clone <bare 저장소 경로>` 로 작업 폴더를 만들어 그것을 엽니다                                            |
| `지원하지 않음: sha256 object format`                  | SHA-256 으로 만든 저장소                                                | 열 수 없습니다                                                                                                                           |
| 상태 바 **git 없음**                                   | git 을 찾지 못함                                                        | [10.1](#101-git-이-없거나-버전이-낮을-때)                                                                                                |
| 폴더 탭에 있어야 할 저장소가 없음                      | 3단계보다 깊거나, 숨김 폴더·`node_modules` 같은 건너뛰는 폴더 안에 있음 | Project 도구 창의 **다시 스캔**. 규칙은 [2.1](2-저장소와-폴더-열기.md#폴더-안에서-저장소를-찾는-규칙)                                    |
| Project 트리 저장소 행의 ⚠, 개요 표의 빨간 저장소 이름 | 그 저장소의 상태를 읽지 못함                                            | 마우스를 올려 이유를 봅니다. 권한이면 [10.5](#105-권한이-없다는-안내가-뜰-때), 잠금이면 [10.2](#102-indexlock-이-남아-있을-때)           |
- 저장소가 문서·데스크탑·다운로드·iCloud Drive 같은 보호된 위치에 있으면 macOS 가 읽기를 막을 수 있습니다. [10.5](#105-권한이-없다는-안내가-뜰-때)를 보세요.
- 폴더를 끌어다 놓아 열어도 판정은 같습니다.

## 10.4 파일이 열리지 않을 때

편집기의 파일 보기는 읽기 전용이고, 아래 파일은 내용 대신 안내를 보입니다([3.5 열 수 없는 파일](3-화면-둘러보기.md#열-수-없는-파일)).

| 보이는 것                                                  | 원인                                | 해결                                         |
| ---------------------------------------------------------- | ----------------------------------- | -------------------------------------------- |
| **바이너리 파일이라 내용을 보이지 않습니다** (크기)        | 글자가 아닌 파일(그림·압축 파일 등) | 그 파일을 여는 앱으로 엽니다                 |
| **UTF-8 이 아닌 텍스트라 보이지 않습니다** (크기)          | EUC-KR 등 다른 인코딩의 글자 파일   | 외부 에디터로 엽니다                         |
| **파일이 너무 커서 보이지 않습니다**: 크기 (상한 1.0 MB)   | 1.0 MB 를 넘는 파일                 | 외부 에디터로 엽니다                         |
| **심볼릭 링크는 열지 않습니다 (대상을 따라가지 않습니다)** | 링크는 따라가지 않음                | 링크가 가리키는 파일을 직접 엽니다           |
| **FIFO·소켓·장치 같은 특수 파일은 열 수 없습니다**         | 보통 파일이 아님                    | 열 필요가 없는 파일입니다                    |
| **파일이 없습니다 (지워졌거나 옮겨졌습니다)**              | 탭을 연 뒤 파일이 지워지거나 옮겨짐 | Project 트리를 **새로고침** 하고 다시 엽니다 |
| **권한이 없어 파일을 읽지 못했습니다**                     | 읽기 권한이 없음                    | [10.5](#105-권한이-없다는-안내가-뜰-때)      |
| `파일을 읽지 못했습니다: <이유>`                           | 그 밖의 오류                        | **다시 시도**. 계속되면 이유를 확인합니다    |

Project 트리에서 흐리게 보이는 행(심볼릭 링크·특수 파일·이름이 너무 긴 파일)은 열 수 없습니다. 마우스를 올리면 이유가 보입니다([3.4](3-화면-둘러보기.md#열-수-없는-항목)).

### 외부 에디터로 열기

- 저장소 탭에서 바뀐 파일이면 Commit 도구 창에서 그 파일을 우클릭하고 **에디터에서 열기** 를 고릅니다.
- 바뀌지 않은 파일이면 Project 트리에서 파일을 우클릭해 **경로 복사** 를 고른 뒤 에디터에서 그 경로를 엽니다. 또는 **에디터에서 열기**(`⌘⇧E`, 저장소 탭)로 저장소 폴더를 에디터에서 열고 그 안에서 찾습니다.
- 쓸 에디터는 **설정…**(`⌘,`)에서 바꿉니다([8.2](8-설정.md#82-외부-앱)).

diff 탭에서 큰 파일은 `큰 파일: 전체 N줄 중 앞부분만 표시` 와 **전체 보기** 가 보입니다. **전체 보기** 를 누르면 나머지를 읽습니다([4.1](4-일상-작업.md#작업-트리-diff-탭)).

## 10.5 권한이 없다는 안내가 뜰 때

### 증상

- Project 트리에서 폴더를 펼치면 **권한이 없어 읽지 못했습니다** 가 보입니다.
- 파일 보기에 **권한이 없어 파일을 읽지 못했습니다** 가 보입니다.

### 원인

그 폴더나 파일을 읽을 권한이 없습니다. 두 가지 경우가 있습니다.

- macOS 개인정보 보호: 문서·데스크탑·다운로드 폴더, iCloud Drive, 외장 디스크, 네트워크 볼륨은 앱마다 허용을 받아야 읽을 수 있습니다. 터미널에서는 되는데 mGit 에서만 안 되면 이 경우일 가능성이 큽니다.
- 파일 권한: 파일의 소유자나 권한 설정이 읽기를 막고 있습니다.

mGit 에는 macOS 보호 폴더 전용 안내가 없습니다. 위 글자만 보입니다.

### 해결

macOS 개인정보 보호 때문이면 다음과 같이 허용합니다(macOS 의 일반 절차입니다).

1. 시스템 설정 → 개인정보 보호 및 보안 → 파일 및 폴더 를 엽니다.
2. mGit 아래에서 그 위치(문서 폴더 등)를 켭니다.
3. 목록에 mGit 이 없거나 여러 위치를 쓰면 같은 화면의 전체 디스크 접근 권한 에서 mGit 을 켭니다. 없으면 + 로 응용 프로그램 폴더의 mGit 을 더합니다.
4. mGit 을 끝내고(`⌘Q`) 다시 켭니다.

처음 그 위치를 열 때 macOS 가 접근을 묻는 창을 띄우면 허용을 누르면 됩니다.

파일 권한 때문이면 터미널에서 `ls -l <경로>` 로 소유자와 권한을 확인합니다.

> [!TIP]
> 저장소를 보호된 위치 밖(예: `~/work`)에 두면 이런 일이 생기지 않습니다.

## 10.6 인증을 묻거나 실패할 때

### 자격 증명을 묻는 대화상자

clone·fetch·pull·push 처럼 원격과 주고받을 때 git·ssh 가 사용자 이름·비밀번호·SSH 키 암호를 물으면 앱이 대화상자를 띄웁니다.

| 제목                | 묻는 것                                                      |
| ------------------- | ------------------------------------------------------------ |
| **사용자 이름**     | https 주소의 사용자 이름                                     |
| **비밀번호 / 토큰** | https 주소의 비밀번호. GitHub 는 개인 액세스 토큰을 적습니다 |
| **SSH 키 암호**     | SSH 키에 걸어 둔 암호                                        |
| **입력**            | 그 밖의 질문                                                 |
1. 본문의 `대상: <주소>` 와 그 아래 git 의 질문을 확인합니다.
2. 칸에 값을 적습니다.
3. 다음에도 쓰려면 **OS 키체인에 저장** 을 켜 둡니다. 처음에 켜져 있습니다(**입력** 대화상자만 꺼져 있음).
4. **보내기** 를 누릅니다. 그만두려면 **취소** 를 누릅니다. 취소하면 그 명령은 실패합니다.

- 키체인에 저장해 둔 값이 있으면 묻지 않고 그 값을 씁니다.
- 여러 명령이 한꺼번에 물으면 대화상자가 하나씩 차례로 뜹니다.
- 5분 안에 답하지 않으면 그 요청은 취소되고 `자격 증명 요청이 시간을 넘겨 취소됐습니다: <대상>` 알림이 뜹니다. 그 명령은 실패하니 다시 실행합니다.
- git 의 credential helper(macOS 키체인 helper 등)에 이미 값이 있으면 git 이 그 값을 먼저 쓰므로 대화상자가 뜨지 않습니다.

### 인증에 실패하면

- 전용 대화상자는 없습니다. 빨간 오류 줄(폴더 탭은 결과 알림)에 `git … 실패: <git 메시지>` 가 그대로 보입니다. 예: `Authentication failed`, `Permission denied (publickey)`, `Invalid username or password`.
- **원격 tag 확인** 이 인증에서 실패하면 오류 줄 대신 브랜치 칸 **태그** 묶음의 요약과 태그 문서 머리에 **인증 실패** 가 붙습니다. 앞서 확인한 결과는 지우지 않습니다. → [10.9](#tag-작업이-거부되거나-실패했을-때)
- 서버가 거부한 값이 앱이 키체인에서 꺼내 준 값(또는 방금 저장한 값)이면, 앱이 그 값을 키체인에서 지웁니다. 같은 작업을 다시 하면 대화상자가 다시 뜨니 맞는 값을 적습니다.
- `Permission denied (publickey)` 는 SSH 키가 호스팅에 등록되지 않았거나 다른 키를 쓰고 있다는 뜻입니다. → [8.6 SSH 키](8-설정.md#86-ssh-키)

### 저장된 자격 증명 지우기

잘못 저장한 값을 지우려면 다음과 같이 합니다.

1. 팔레트(`⌘⇧P`)에서 **호스팅 계정…** 을 엽니다.
2. **저장된 자격 증명** 의 **대상 (예: https://github.com)** 칸에 대상을 적습니다. 최근에 물어본 대상은 목록에서 고를 수 있습니다.
3. **지우기** 를 누릅니다. 그 대상의 사용자 이름과 비밀번호를 함께 지우고 `저장된 자격 증명을 지웠습니다: <대상>` 알림이 뜹니다.

자세한 화면은 [8.4 호스팅 계정](8-설정.md#84-호스팅-계정)에 있습니다.

이 단추는 mGit 이 키체인에 저장한 값만 지웁니다. git 의 credential helper 에 저장된 값은 터미널에서 지웁니다.

```sh
printf 'protocol=https\nhost=github.com\n\n' | git credential reject
```

## 10.7 저장소 세션 3개 한도

### 증상

폴더 탭에서 다음 글자가 보입니다.

- 알림 `저장소 세션 3개가 모두 쓰이는 중이라 더 열 수 없습니다. 열린 대화상자나 진행 중인 작업을 끝낸 뒤 다시 시도하세요`
- 작업 진행 띠의 줄에 `저장소 세션 3개가 모두 쓰이는 중이라 지금 실행할 수 없습니다. 열린 대화상자·진행 중인 작업·저장하지 않은 충돌 편집을 끝내세요` 가 보이고 단추가 꺼짐
- 알림 `<저장소> 의 대화상자·작업이 끝난 뒤에 다른 저장소의 기능을 쓸 수 있습니다`

### 원인

폴더 탭은 파일 히스토리·Blame·작업 트리 diff·충돌 해결·작업 진행 띠의 단추를 쓸 때 그 저장소의 "저장소 세션"을 뒤에서 엽니다. 폴더 탭 하나가 동시에 잡는 세션은 3개까지입니다.

넷째가 필요하면 앱이 가장 오래 안 쓴 세션을 저절로 닫고 엽니다. 다만 다음 세션은 닫지 않습니다.

- Git 작업이 도는 중인 세션
- 저장하지 않은 충돌 편집(초안)이 있는 세션
- 파일 히스토리·Blame 대화상자나 그 저장소의 안내 대화상자가 열려 있는 세션
- 지금 편집기에 보이는 탭의 세션

세 세션이 모두 이런 상태이면 더 열 수 없어 위 안내가 뜹니다. 그 저장소를 저장소 탭으로 따로 열어 둔 것은 셋에 세지 않습니다.

마지막 알림은 한도와 따로, 다른 저장소의 대화상자나 작업이 끝나지 않아 그 저장소에서 떠날 수 없을 때 뜹니다.

### 해결

1. 열려 있는 파일 히스토리·Blame 대화상자와 안내 대화상자를 닫습니다.
2. 도는 작업이 끝나기를 기다립니다(툴바의 진행 표시).
3. 충돌 편집기에 저장하지 않은 편집이 있으면 **저장 후 stage** 하거나 버립니다([5.6](5-가끔-하는-작업.md#저장하지-않은-편집초안)).
4. 다시 시도합니다.

> [!TIP]
> 여러 저장소를 오가며 충돌을 풀거나 히스토리를 깊게 볼 때는 그 저장소들을 저장소 탭으로 여세요([2.2](2-저장소와-폴더-열기.md#폴더-탭에서-저장소-탭으로-열기)). 저장소 탭에는 이 한도가 없습니다.

## 10.8 Pull Requests 에 계정이 없다고 나올 때

### 증상

저장소 탭의 Pull Requests 도구 창(GitLab 은 Merge Requests)에 **계정을 연결하면 PR 을 볼 수 있습니다.** 와 **계정 연결…** 이 보입니다.

### 원인

원격(`origin`, 없으면 첫 원격) 주소의 호스트와 같은 호스트의 호스팅 계정이 연결돼 있지 않습니다.

### 해결

1. **계정 연결…** 을 누르거나 팔레트의 **호스팅 계정…** 에서 계정을 더합니다([8.4](8-설정.md#84-호스팅-계정)). 호스트는 원격 주소의 호스트와 똑같이 적습니다(예: `github.com`, 회사 GitLab 이면 `gitlab.example.com`).
2. 그 저장소 탭을 닫고 다시 엽니다. 원격과 계정 정보는 탭을 열 때 읽으므로, 계정을 연결하기만 해서는 바뀌지 않습니다. 머리의 **새로고침** 은 PR 목록만 다시 읽습니다.

- 원격을 더하거나 주소를 바꾼 뒤에도 탭을 다시 열어야 반영됩니다([5.5](5-가끔-하는-작업.md#55-원격-관리하기)).
- 원격이 GitHub·GitLab 이 아니어도(예: Bitbucket) 단추가 보일 수 있습니다. 앱이 호스트 이름에 `gitlab` 이 없으면 GitHub 로 짐작하기 때문입니다([5.9](5-가끔-하는-작업.md#보이는-조건)). 이런 원격은 계정을 연결해도 PR 을 볼 수 없으니 도구 창을 쓰지 않으면 됩니다.
- 계정이 있는데 목록 대신 오류 글자가 보이면 그 글자를 확인합니다. 토큰이 만료됐으면 [8.4](8-설정.md#84-호스팅-계정)에서 계정을 지우고 다시 더합니다.

## 10.9 push·pull 이 거부되거나 단추가 꺼져 있을 때

### 거부됐을 때

| 보이는 것                                                      | 뜻                                    | 할 일                                                                   |
| -------------------------------------------------------------- | ------------------------------------- | ----------------------------------------------------------------------- |
| **원격에 새 commit 이 있습니다** 대화상자                      | 원격에 내가 받지 않은 commit 이 있음  | **pull 후 push**. 원격을 덮어써야 할 때만 **force-with-lease 로 push**  |
| **강제 push 가 거부됐습니다** 대화상자                         | 그사이 원격이 또 바뀜                 | **pull** 로 받아 확인한 뒤 다시 push                                    |
| **업스트림이 없습니다** 대화상자                               | 연결된 원격 branch 가 없음            | **업스트림 지정 후 push**                                               |
| `detached HEAD 에서는 push 할 수 없습니다`                     | 분리된 HEAD                           | 로그 행 우클릭 → **여기서 branch 만들기…** 로 branch 를 만든 뒤 push    |
| `원격이 없습니다. 먼저 원격을 추가하세요`                      | 원격이 하나도 없음                    | 툴바 **원격…** → **추가…**([5.5](5-가끔-하는-작업.md#55-원격-관리하기)) |
| `원격이 여러 개라 보낼 곳을 정할 수 없습니다. 원격을 고르세요` | 업스트림이 없고 `origin` 도 없음      | **Push** 옆 ⌄ 에서 원격을 고릅니다                                      |
| 폴더 탭 일괄 push·pull 결과의 **실패**                         | 폴더 탭은 대화상자 없이 실패로만 알림 | 그 저장소를 저장소 탭으로 열어 처리합니다                               |
| `Authentication failed` 같은 인증 오류                         | 자격 증명이 틀리거나 없음             | [10.6](#106-인증을-묻거나-실패할-때)                                    |

대화상자의 자세한 뜻은 [4.3 push 중에 뜨는 대화상자](4-일상-작업.md#push-중에-뜨는-대화상자)에 있습니다.

> [!NOTE]
> 거부 대화상자의 분류는 git 메시지를 보고 짐작한 것입니다. 원격을 덮어쓰는 **force-with-lease 로 push** 를 고르기 전에 Git 콘솔([6.5](6-실수했을-때.md#65-실행된-명령-보기))에서 git 의 실제 출력을 확인하세요.

폴더 탭의 일괄 pull 은 처음 방식이 ff-only 라서, 내 commit 과 원격 commit 이 갈라진 저장소는 실패합니다. 그 저장소를 저장소 탭으로 열어 툴바 **Pull** 옆에서 방식을 골라 pull 합니다([4.3](4-일상-작업.md#43-fetchpullpush-하기)).

### tag 작업이 거부되거나 실패했을 때

tag 의 push·원격 삭제·가져오기는 tag 마다 결과를 냅니다. 브랜치 칸·로그 메뉴에서 했으면 빨간 오류 줄에, 태그 문서에서 했으면 문서의 결과 칸에 실패한 tag 와 사유가 `v1 (사유)` 로 보입니다. → [5.4 tag](5-가끔-하는-작업.md#54-tag)

| 보이는 것                                                                                | 뜻                                                                                             | 할 일                                                                                                                          |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **태그** 묶음 요약·태그 문서 머리의 **인증 실패**                                        | 원격 tag 확인에서 자격 증명이 거부됨. 앞서 확인한 결과는 그대로                                | [10.6](#106-인증을-묻거나-실패할-때)대로 자격 증명을 고친 뒤 **원격 tag 확인** 을 다시 누릅니다                                |
| 같은 자리의 **연결 실패**                                                                | 원격에 닿지 못함(오프라인, 주소가 틀림, 원격 저장소가 없음)                                    | 네트워크와 원격 주소(**원격…**)를 확인한 뒤 다시 확인합니다                                                                    |
| 같은 자리의 **확인 실패**                                                                | 그 밖의 이유로 확인하지 못함                                                                   | Git 콘솔([6.5](6-실수했을-때.md#65-실행된-명령-보기))에서 `ls-remote` 의 출력을 봅니다                                         |
| `서버가 거부함: <사유>`                                                                  | 원격 저장소의 hook·보호 규칙이 거부함. branch push 에서도 같고, 강제 push 대화상자는 뜨지 않음 | 사유를 읽고 원격 저장소의 규칙을 확인합니다. 강제로 풀 수 없습니다                                                             |
| 안내 `<원격> 에 이름이 같은 다른 tag <이름> 이(가) 있습니다`                             | push 하려는 tag 와 이름은 같고 내용이 다른 tag 가 원격에 있음. 아무것도 바뀌지 않음            | **확인**. 원격을 로컬 것으로 바꾸려면 **원격 tag 를 로컬 것으로 덮어쓰기…**([5.4](5-가끔-하는-작업.md#원격과-다른-tag-맞추기)) |
| `v1 (원격이 그사이 바뀜)`                                                                | 원격 삭제·덮어쓰기 직전에 확인한 tag 가 그사이 바뀜(다른 사람이 바꿈). 원격은 그대로           | **원격 tag 확인** 으로 지금 상태를 본 뒤 다시 합니다                                                                           |
| `v1 (결과를 알 수 없음 — 원격을 다시 확인하세요)`                                        | 취소나 연결 끊김으로 반영됐는지 모름                                                           | **원격 tag 확인** 으로 상태를 본 뒤 필요하면 다시 합니다. 태그 문서에서는 **실패한 것 다시 시도**                              |
| `<원격> 에 없는 tag 가 섞여 아무것도 가져오지 않았습니다. 원격 확인 뒤 다시 시도하세요.` | 가져올 tag 중 하나라도 원격에 없으면 git 이 전체를 멈춤. 아무것도 받지 않음                    | 태그 문서에서 **원격 확인** 을 누른 뒤 **원격에만** 인 tag 만 골라 다시 가져옵니다                                             |

### 단추가 꺼져 있을 때

저장소 탭의 **Fetch**·**Pull**·**Push** 는 다음일 때 꺼집니다. 마우스를 올리면 사유가 보이는 곳도 있습니다.

- 원격이 없음(셋 모두)
- 업스트림이 없거나 업스트림이 원격에서 지워짐(**원격 삭제됨**, **Pull**)
- 분리된 HEAD(**Push**)
- 다른 Git 작업이 도는 중, 또는 merge·rebase 등이 멈춰 있는 중(셋 모두)

멈춘 작업은 작업 진행 띠에서 **Continue** 나 **Abort** 로 끝냅니다([5.6](5-가끔-하는-작업.md#56-충돌-해결하기)). 폴더 탭의 일괄 단추는 일괄 작업이 도는 동안 꺼집니다.

## 10.10 있어야 할 것이 안 보일 때

| 보이는 것                                             | 이유                                                 | 할 일                                                                             |
| ----------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------- |
| 로그 자리에 **필터와 일치하는 커밋이 없습니다**       | 필터 조건에 맞는 commit 이 없음                      | **필터 지우기**. 필터 바의 **모두 지우기** 도 같음([4.5](4-일상-작업.md#필터-바)) |
| 필터 바 텍스트 칸에 **적용 전**                       | 적은 글자를 아직 적용하지 않음                       | 칸에서 Enter                                                                      |
| 그래프 선이 사라지고 **목록** 배지                    | 텍스트·작성자 조건이나 **머지 제외** 가 걸림         | 정상입니다. 조건을 풀면 그래프로 돌아옵니다                                       |
| 원격에만 있는 commit 이 안 보임                       | **보기 옵션** 의 **원격 숨기기**                     | **보기 옵션** 에서 끕니다([4.5](4-일상-작업.md#보기-옵션))                        |
| merge 로 들어온 commit 이 안 보임                     | **첫 부모만** 이나 **머지 제외**                     | **보기 옵션** 에서 끕니다                                                         |
| 한 branch 의 이력만 보임                              | **이 branch 만 그래프에 표시** 로 branch 조건이 걸림 | 필터 바 branch 조건의 ×                                                           |
| 저장소 탭 로그가 한 폴더의 commit 만 보임             | 모듈 범위(Project 트리 위 `범위: <이름>` 띠)         | 띠 끝의 ×(**범위 해제**)([5.8](5-가끔-하는-작업.md#모듈-범위))                    |
| 폴더 탭 로그에 저장소 하나만 보임                     | **이 저장소만 보기** 나 **저장소** 드롭다운          | 행 메뉴의 **모든 저장소 보기**, 또는 드롭다운의 체크를 모두 풂                    |
| 폴더 탭 통합 로그에 오래된 commit 이 없음             | 저장소마다 최근 10,000개만 읽음                      | 그 저장소를 저장소 탭으로 엽니다                                                  |
| 상세 칸에 **고른 커밋은 지금 필터의 로그에 없습니다** | 옮겨 간 commit 이 필터에 걸려 로그에 없음            | **필터 지우고 보기**                                                              |
| 원격의 새 commit 이 안 보임                           | 아직 fetch 하지 않음. 폴더 탭은 자동 fetch 를 안 함  | 툴바 **Fetch**([4.3](4-일상-작업.md#자동-fetch와-배지))                           |
| 원격 branch(`origin/x`)가 사라짐                      | 원격에서 지워져 fetch 의 `--prune` 이 정리함         | [7.2](7-알아-두면-좋은-동작.md#72-확인-없이-바로-바뀌는-것)                       |
| Project 트리에 지운 파일이 없음                       | 디스크에 없는 파일은 트리에 나오지 않음              | Commit 도구 창에서 봅니다([4.1](4-일상-작업.md#41-변경-확인하기))                 |
| Project 트리 폴더 끝에 `… N개 더 보기`                | 항목이 많아 일부만 읽음                              | 그 줄을 누르거나 Enter([3.4](3-화면-둘러보기.md#안내-줄))                         |
| 앱 밖에서 바꾼 것이 화면에 없음                       | 아직 다시 읽지 않음                                  | 툴바 **새로고침**(`⌘R`)                                                           |

## 10.11 화면이 느릴 때

큰 저장소에서 느리면 다음을 해 봅니다.

- 저장소 탭 로그 위에 `추적 파일 N개: fsmonitor 를 켜면 상태 조회가 빨라집니다` 배너가 보이면 **fsmonitor 켜기** 를 누릅니다. 이 저장소의 git 설정 `core.fsmonitor`·`core.untrackedCache` 를 켭니다. 추적 파일이 2만 개 이상이고 fsmonitor 가 꺼져 있을 때 보입니다.
- 같은 자리에 **commit 이 많습니다. commit-graph 를 만들면 그래프 로드가 빨라집니다.** 가 보이면 **commit-graph 생성** 을 누릅니다. commit 이 2만 개 이상이고 commit-graph 파일이 없을 때 보입니다.
- fsmonitor 는 배너를 닫았어도 **저장소 설정…** 의 상태 조회 최적화에서 켤 수 있습니다([8.7](8-설정.md#87-저장소-설정)).
- 폴더 탭이 느리면 폴더 설정의 동시 실행 수와 자동 갱신 간격을 줄여 봅니다([8.8](8-설정.md#88-폴더-설정)).
- 새로 받는 큰 저장소는 clone 의 **깊이 (비우면 전체)** 나 **파일 내용은 필요할 때 받기 (--filter=blob:none)** 로 받으면 빠릅니다([2.4](2-저장소와-폴더-열기.md#24-clone-하기)).

## 10.12 알 수 없는 오류를 알릴 때

mGit 에는 로그 파일을 남기는 기능이 없습니다. 문제를 알릴 때는 Git 콘솔의 기록을 복사해 보냅니다.

1. `⌘J` 로 Git 도구 창의 **콘솔** 탭을 엽니다. 폴더 탭이면 저장소 이름을 눌러 그 저장소의 기록만 볼 수 있습니다.
2. 실패한 명령의 줄을 찾습니다. 줄 끝에 `종료 <코드>` 가 보이고, 0 이 아니면 실패입니다.
3. 줄의 **복사** 를 누릅니다. 명령줄이 복사됩니다. 줄에 포커스를 두고 `⌘C` 를 눌러도 됩니다.
4. 명령을 누르면 오류 출력이 펼쳐집니다. 글자를 끌어 골라 `⌘C` 로 복사합니다.
5. 함께 적습니다: 화면에 보인 오류 글자(빨간 칸·줄은 마우스를 올리면 전체가 보임), 상태 바의 git 버전, 무엇을 하다가 났는지.

- 콘솔 기록은 탭마다 최근 500개까지 앱 안에만 남습니다. 탭을 닫거나 앱을 끄면 사라지니 오류가 난 직후에 복사하세요.
- 폴더 탭의 콘솔에는 쓰기·네트워크 명령만 쌓입니다. 읽기 명령까지 보려면 그 저장소를 저장소 탭으로 엽니다([3.9](3-화면-둘러보기.md#39-콘솔과-터미널)).
- 주소에 든 비밀번호·토큰은 기록에서 가려집니다. 그래도 경로와 저장소 이름이 들어가니 보내기 전에 확인하세요.

그 밖에 보일 수 있는 글자는 다음과 같습니다.

| 보이는 것                   | 할 일                                                                  |
| --------------------------- | ---------------------------------------------------------------------- |
| **세션을 찾을 수 없습니다** | 그 탭을 닫고 다시 엽니다                                               |
| **알 수 없는 오류**         | 위 순서로 콘솔 기록을 확인하고 알립니다                                |
| `git … 실패: <git 메시지>`  | git 이 거부한 이유가 그대로입니다. 메시지를 읽고, 모르겠으면 위 순서로 |

자세한 콘솔 사용법은 [6.5 실행된 명령 보기](6-실수했을-때.md#65-실행된-명령-보기)에 있습니다.
