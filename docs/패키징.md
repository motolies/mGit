# 패키징

mGit 을 `.app`·`.dmg` 로 만들고, 설치하고, 다른 Mac 에서 여는 방법입니다. 1~3절과 6~9절은 직접 만드는 사람을 위한 것이고, 받은 dmg 를 설치하는 사람은 4·5절만 보면 됩니다.

기준: 브랜치 `feat/tag-management` · 커밋 `aedc0b6` · 2026-11-23

## 0. 한눈에

준비물(1절)을 갖춘 저장소 루트에서 아래 두 줄을 실행합니다.

```bash
echo "$VITE_MGIT_MOCK"   # 빈 줄이어야 합니다(2절 WARNING)
pnpm build
```

결과물은 두 개입니다.

| 결과물 | 경로                                               | 크기 |
| ------ | -------------------------------------------------- | ---- |
| `.app` | `target/release/bundle/macos/mGit.app`             | 47MB |
| `.dmg` | `target/release/bundle/dmg/mGit_0.1.0_aarch64.dmg` | 13MB |
- 파일 이름의 `0.1.0` 은 앱 버전(7절), `aarch64` 는 Apple Silicon 전용이라는 뜻입니다. Intel Mac 에서도 돌게 하려면 3절을 봅니다.
- 걸린 시간은 빈 `target/` 에서 1분 45초, release 빌드를 해 둔 뒤에는 47초~1분 27초였습니다(2절 표).
- 남에게 줄 것은 `.dmg` 하나입니다. 받은 사람은 4·5절을 따릅니다.

## 1. 처음 한 번

- 준비물(Command Line Tools, Rust, Node.js, pnpm)은 [빌드·테스트 1절](빌드-테스트.md#1-준비물)과 같고, 의존성 설치는 [2절](빌드-테스트.md#2-소스-받기와-첫-설치)입니다. 따로 더 설치할 것은 없습니다. 서명에 쓰는 `codesign` 은 macOS 에 들어 있습니다.
- universal(3절)을 만들 때만 Intel 용 Rust 타깃을 한 번 추가합니다. Apple Silicon Mac 에 rustup 을 기본값으로 설치하면 Apple Silicon 용(`aarch64-apple-darwin`)만 있습니다.

  ```bash
  rustup target add x86_64-apple-darwin
  rustup target list --installed   # aarch64-apple-darwin 과 x86_64-apple-darwin 이 보이면 됩니다
  ```

## 2. 만들기

`.app`·`.dmg` 를 만들려면 저장소 루트에서 `pnpm build` 를 실행합니다.

> [!WARNING]
> 셸에 `VITE_MGIT_MOCK` 이 남은 채 빌드하면 목 앱이 만들어집니다. 목 앱은 실제 저장소 대신 합성 데이터를 보여 주고, 그 안에서 한 작업은 저장소에 반영되지 않습니다. 빌드 전에 `echo "$VITE_MGIT_MOCK"` 가 빈 줄인지 보고, 값이 있으면 `unset VITE_MGIT_MOCK VITE_MGIT_MOCK_SCENE` 으로 지웁니다. → [빌드·테스트 4절](빌드-테스트.md#4-목-모드--코어-없이-화면만-보기)
1. 목 변수가 비어 있는지 확인합니다(위 WARNING).
2. 빌드합니다.

   ```bash
   pnpm build
   ```

3. 터미널 끝에 `Finished 2 bundles at:` 과 결과물 경로 두 줄이 나오면 끝입니다.

`pnpm build` 는 화면을 빌드하고(`beforeBuildCommand` → `apps/desktop/dist`), Rust 를 release 로 컴파일한 뒤, `.app` 을 만들어 서명하고 `.dmg` 로 묶습니다. 출력의 주요 줄은 다음과 같습니다(경로는 줄임).

```text
     Running beforeBuildCommand `pnpm build:web`
    Finished `release` profile [optimized + debuginfo] target(s) in 1m 05s
    Bundling mGit.app (…/target/release/bundle/macos/mGit.app)
     Signing with identity "-"
        Warn skipping app notarization, no APPLE_ID & APPLE_PASSWORD & APPLE_TEAM_ID or APPLE_API_KEY & APPLE_API_ISSUER & APPLE_API_KEY_PATH environment variables found
    Bundling mGit_0.1.0_aarch64.dmg (…/target/release/bundle/dmg/mGit_0.1.0_aarch64.dmg)
    Finished 2 bundles at:
        …/target/release/bundle/macos/mGit.app (46.88 MiB)
        …/target/release/bundle/dmg/mGit_0.1.0_aarch64.dmg (12.80 MiB)
```

- 화면 빌드 중에 `(!) Some chunks are larger than 500 kB after minification` 경고가 나옵니다. 큰 화면 코드 묶음이 있다는 안내이고 빌드는 계속됩니다.
- `Signing with identity "-"` 는 임시(ad-hoc) 서명입니다(5절).
- `Warn skipping app notarization …` 은 Apple 공증에 쓸 값이 없어 공증을 건너뛴다는 뜻입니다. 이 저장소에서는 늘 나옵니다(6절).
- 같은 버전이면 이전 결과물을 덮어씁니다. `bundle/dmg/` 의 `bundle_dmg.sh`·`icon.icns` 는 dmg 를 만들 때 쓴 파일입니다.

걸린 시간은 다음과 같습니다. 잰 기계는 [빌드·테스트 0절](빌드-테스트.md#0-한눈에)과 같은 Apple M4 Pro(14코어)·메모리 24GB 입니다.

| 경우                                    | 전체     | Rust 컴파일 | 조건                                                                 |
| --------------------------------------- | -------- | ----------- | -------------------------------------------------------------------- |
| 처음(빈 `target/`)                      | 1분 45초 | 1분 23초    | 컴파일 단위 349개. crate 는 이미 받아 둔 상태. `--bundles dmg` 로 잼 |
| release 빌드를 해 둔 뒤 다시            | 1분 27초 | 1분 5초     | 3주 전 release 빌드 뒤 바뀐 crate 27개                               |
| 고친 것 없이 바로 다시(`--bundles app`) | 47초     | 45초        | `mgit-desktop` 1개만 다시 컴파일                                     |

고친 것이 없어도 `mgit-desktop` 은 매번 다시 컴파일합니다. 화면 빌드 결과를 실행 파일 안에 넣기 때문입니다. 화면 빌드(vite) 자체는 0.4초 남짓입니다.

### `.app` 이나 `.dmg` 하나만 만들기

하나만 필요하면 `--bundles` 로 고릅니다.

```bash
pnpm build --bundles app   # .app 만
pnpm build --bundles dmg   # .dmg 만
```

- `pnpm build` 뒤에 붙인 인자는 `tauri build` 에 그대로 갑니다. `--` 는 필요 없습니다. 출력 첫 줄들에 `$ tauri build --bundles app` 처럼 보이면 전달된 것입니다.
- `--bundles app` 은 `.dmg` 를 건드리지 않습니다. 폴더에 있던 dmg 는 예전 것 그대로 남습니다.
- `--bundles dmg` 도 안에서 `.app` 을 먼저 만들지만, dmg 를 만든 뒤 그 `.app` 을 지웁니다(출력에 `Cleaning …/mGit.app`). `bundle/macos/` 에는 남는 것이 없습니다.
- macOS 에서 고를 수 있는 값은 `app`·`dmg`(와 `ios`)입니다. 다른 옵션은 `apps/desktop` 폴더에서 `./node_modules/.bin/tauri build --help` 로 봅니다.

## 3. Apple Silicon·Intel 둘 다 도는 앱 (universal)

Intel Mac 에서도 돌게 하려면 universal 로 만듭니다. 2절의 결과물은 Apple Silicon 에서만 돕니다.

> [!NOTE]
> 이 절은 실제로 만들어 보지 않았습니다(확인 전). 명령은 tauri-cli 2.12.4 의 `tauri build --help` 와 Tauri 문서를 따른 것입니다.
1. Intel 용 Rust 타깃이 없으면 추가합니다(1절).
2. universal 로 빌드합니다.

   ```bash
   pnpm build --target universal-apple-darwin
   ```

3. 결과물은 `target/universal-apple-darwin/release/bundle/` 아래에 생깁니다.

| 결과물 | 경로                                                                        |
| ------ | --------------------------------------------------------------------------- |
| `.app` | `target/universal-apple-darwin/release/bundle/macos/mGit.app`               |
| `.dmg` | `target/universal-apple-darwin/release/bundle/dmg/mGit_0.1.0_universal.dmg` |
- Apple Silicon 용과 Intel 용을 따로 컴파일해 하나로 합치므로 2절보다 오래 걸리고 파일도 큽니다(재지 않음).
- 실행 파일에 든 아키텍처는 `lipo -archs <앱>/Contents/MacOS/mgit-desktop` 으로 봅니다. 2절의 결과물은 `arm64` 하나이고, universal 이면 `x86_64` 와 `arm64` 가 함께 보여야 합니다.
- 최소 macOS 는 둘 다 15.0 입니다(`tauri.conf.json` 의 `minimumSystemVersion`).

## 4. 설치하기

받은 `.dmg` 로 설치하려면 다음과 같이 합니다. [사용법 1.2](사용법/1-설치와-첫-실행.md#12-앱-설치하기)와 같은 절차를 조금 더 자세히 적었습니다.

1. `.dmg` 파일을 더블클릭합니다. mGit 아이콘과 `Applications` 폴더 바로가기가 든 창이 열립니다.
2. mGit 아이콘을 `Applications` 바로가기 위로 끌어 놓습니다. 응용 프로그램 폴더로 복사됩니다.
3. 창을 닫고, Finder 사이드바의 위치 목록에서 dmg 디스크 옆 꺼내기 단추(⏏)를 눌러 꺼냅니다. dmg 파일은 지워도 됩니다.
4. 응용 프로그램 폴더에서 mGit 을 엽니다. 다른 Mac 에서 만든 dmg 라서 경고가 뜨면 5절을 따릅니다.

받을 Mac 이 Intel 이면 `aarch64` dmg 로는 열리지 않습니다. universal dmg(3절)를 받습니다. Apple 메뉴 > 이 Mac에 관하여 에서 칩이 Apple M 으로 시작하면 Apple Silicon, 프로세서가 Intel 이면 Intel 입니다.

### 이미 설치돼 있으면

새 버전으로 바꾸려면 열려 있는 mGit 을 `⌘Q` 로 끝낸 뒤 위 1~3을 똑같이 합니다. Finder 가 같은 이름의 항목이 있다고 물으면 기존 것을 대치하는 쪽을 고릅니다(macOS 표기는 버전마다 다를 수 있음).

- 최근 목록·열린 탭·설정은 앱 파일 밖(데이터 폴더 `~/Library/Application Support/io.github.motolies.mgit/` 등)에 저장되므로 앱을 바꿔도 남습니다. 호스팅 계정 토큰은 키체인에 있습니다. 저장되는 곳은 [사용법 8장](사용법/8-설정.md) 머리의 표에 있습니다.
- 소스에서 `pnpm dev` 로 띄운 앱도 이 데이터 폴더를 함께 씁니다([빌드·테스트 3절](빌드-테스트.md#3-개발-실행)).
- 앱을 지우려면 응용 프로그램 폴더의 mGit 을 휴지통으로 옮깁니다. 데이터 폴더는 남습니다. 버린 파일의 백업 사본([사용법 6.3](사용법/6-실수했을-때.md#63-버린-파일-되살리기))도 이 폴더의 `backups` 에 있으니, 데이터 폴더까지 지울 때는 필요한 것이 없는지 먼저 봅니다.

## 5. 다른 Mac 에서 열기

받은 dmg 로 설치한 mGit 이 경고와 함께 열리지 않으면 이 절을 따릅니다.

### 왜 경고가 뜨나

- mGit 은 임시(ad-hoc) 서명으로 만듭니다(`tauri.conf.json` 의 `"signingIdentity": "-"`). 실행 파일이 만든 뒤 바뀌지 않았다는 것만 보증하고, 누가 만들었는지는 담지 않습니다. Apple 공증도 받지 않았습니다(6절).
- 브라우저 등으로 내려받은 파일에는 macOS 가 격리 속성(`com.apple.quarantine`)을 붙입니다. 격리 속성이 있는 앱을 처음 열면 Gatekeeper 가 서명과 공증을 검사하고, 정식 서명이 아니어서 막습니다.
- 경고 문구는 macOS 버전마다 다릅니다. Apple 이 악성 소프트웨어가 있는지 확인할 수 없다는 경고나, 확인되지 않은 개발자라는 경고가 흔합니다. 경고 창에서는 완료를 눌러 닫습니다(휴지통으로 옮기지 않습니다).
- 직접 빌드한 Mac 의 결과물에는 격리 속성이 붙지 않습니다(`xattr -l` 로 확인).

### 방법 1. 시스템 설정의 "그래도 열기"

macOS 15 부터는 Finder 에서 Control-클릭(우클릭) → 열기로 이 검사를 넘길 수 없습니다([Apple 개발자 소식, 2024-08-06](https://developer.apple.com/news/?id=saqachfa)). 시스템 설정에서 허용합니다.

1. 응용 프로그램 폴더에서 mGit 을 한 번 열어 봅니다. 경고가 뜨면 완료를 누릅니다.
2. Apple 메뉴 > 시스템 설정을 고르고, 사이드바에서 개인정보 보호 및 보안을 누릅니다. 아래로 스크롤해야 할 수 있습니다.
3. 보안 항목으로 내려가 mGit 이 차단됐다는 안내 옆의 단추(열기 또는 "그래도 열기")를 누릅니다.
4. 확인 창이 뜨면 "그래도 열기"를 누릅니다. 이 단추는 앱을 열려고 한 때부터 약 1시간 동안만 쓸 수 있습니다. 시간이 지났으면 1부터 다시 합니다.
5. 로그인 암호를 입력하고 확인을 누릅니다.

단계와 단추 이름은 Apple 지원 문서 [알 수 없는 개발자의 Mac 앱 열기](https://support.apple.com/ko-kr/guide/mac-help/mh40616/mac)(영문 "Open Anyway")를 따랐습니다. macOS 표기는 버전마다 다를 수 있고, 이 문서를 쓸 때 실제 경고 창은 띄워 보지 않았습니다.

### 방법 2. 터미널에서 격리 속성 지우기

터미널을 쓸 줄 알면 격리 속성을 지워도 됩니다.

```bash
xattr -dr com.apple.quarantine /Applications/mGit.app
```

- `-d` 는 속성 지우기, `-r` 은 앱 안의 모든 파일까지라는 뜻입니다. 지운 앱은 내려받지 않은 앱처럼 취급되어 Gatekeeper 가 막지 않습니다.
- 위험: 이 앱에 대해 macOS 의 검사를 건너뛰는 것입니다. 직접 만들었거나 믿을 수 있는 사람에게 받은 파일에만 씁니다.
- 서명은 그대로입니다. 격리 속성을 붙인 복사본으로 시험했을 때 이 명령 뒤 격리 속성이 모두 사라졌고 `codesign --verify` 도 그대로 통과했습니다.

### 서명 상태 확인하기

앱의 서명과 격리 상태는 아래 명령으로 봅니다. 나오는 것은 이 저장소에서 만든 결과물로 확인한 값입니다.

| 명령                                                       | 이 앱에서 나오는 것                         | 뜻                                                      |
| ---------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------- |
| `codesign -dv --verbose=2 /Applications/mGit.app`          | `Signature=adhoc`, `TeamIdentifier=not set` | 임시 서명. 개발자 정보가 없음                           |
| `codesign --verify --deep --strict /Applications/mGit.app` | 출력 없음(종료 코드 0)                      | 서명이 깨지지 않음                                      |
| `spctl -a -vv /Applications/mGit.app`                      | `/Applications/mGit.app: rejected`          | Gatekeeper 가 승인하지 않음. 격리 속성이 있든 없든 같음 |
| `xattr -l /Applications/mGit.app`                          | `com.apple.quarantine: 0081;…` 줄           | 격리 상태. 방법 2 뒤에는 이 줄이 없어짐                 |

`codesign -dv --verbose=2` 출력의 앞부분입니다.

```text
Identifier=io.github.motolies.mgit
Format=app bundle with Mach-O thin (arm64)
CodeDirectory v=20500 size=95889 flags=0x10002(adhoc,runtime) hashes=2990+3 location=embedded
Signature=adhoc
TeamIdentifier=not set
```

- `thin (arm64)` 는 Apple Silicon 전용이라는 뜻입니다.
- dmg 파일 자체는 서명하지 않습니다. dmg 에 `codesign -dv` 를 하면 `code object is not signed at all` 이 나옵니다. 서명은 그 안의 앱에 있습니다.

### 받은 Mac 의 git

mGit 은 git 을 품고 있지 않고 그 Mac 에 설치된 git 을 씁니다. Finder 로 켠 mGit 은 보통 Command Line Tools 의 git(`/usr/bin/git`)을 쓰므로, 받은 Mac 의 터미널에서 `/usr/bin/git --version` 이 2.45 이상이어야 합니다. 없거나 낮으면 앱 상태 바 오른쪽 끝에 **git 없음** 이 보입니다. Homebrew 로 새 git 을 설치해도 Finder 로 켠 앱은 그 git 을 쓰지 않을 수 있으니(확인 전), Command Line Tools 를 설치하거나 올립니다. 자세한 것은 [사용법 1.1](사용법/1-설치와-첫-실행.md#11-요구-사항)과 [10.1](사용법/10-문제-해결.md#101-git-이-없거나-버전이-낮을-때)에 있습니다.

## 6. 정식 서명·공증 (다루지 않음)

경고 없이 열리는 앱을 나눠 주려면 Apple 정식 서명과 공증이 필요합니다. 유료 Apple Developer Program 계정과 그 계정 소유자(Account Holder)가 만든 Developer ID Application 인증서가 있어야 하고, 빌드할 때 환경 변수로 넘깁니다. 서명은 `APPLE_SIGNING_IDENTITY`(또는 `tauri.conf.json` 의 `signingIdentity` 를 바꿈), CI 에서 인증서를 넘길 때는 `APPLE_CERTIFICATE`·`APPLE_CERTIFICATE_PASSWORD`, 공증은 `APPLE_ID`·`APPLE_PASSWORD`·`APPLE_TEAM_ID` 또는 `APPLE_API_KEY`·`APPLE_API_ISSUER`·`APPLE_API_KEY_PATH` 입니다. 공증 값이 없으면 2절의 `Warn skipping app notarization` 처럼 공증을 건너뜁니다. 절차는 Tauri 문서 [macOS Code Signing](https://v2.tauri.app/distribute/sign/macos/)과 그 안의 [Notarization](https://v2.tauri.app/distribute/sign/macos/#notarization) 절에 있습니다. 이 저장소에서는 정식 서명·공증을 해 보지 않았습니다(검증하지 않음).

## 7. 버전 올리기

새 버전을 만들려면 버전이 적힌 11곳을 같은 값으로 바꿉니다. 지금은 모두 `0.1.0` 입니다.

| 파일                                                                         | 적힌 곳                            | 쓰이는 데                                                     |
| ---------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------- |
| `apps/desktop/src-tauri/tauri.conf.json`                                     | `"version"`                        | 앱 버전(`Info.plist`), dmg 파일 이름                          |
| `Cargo.toml`(루트)                                                           | `[workspace.package]` 의 `version` | `version.workspace = true` 인 crate 전부(`mgit-desktop` 포함) |
| `crates/mgit-syntax/Cargo.toml`                                              | `version`                          | 이 crate 만 워크스페이스 값을 따르지 않고 따로 적음           |
| `package.json`(루트), `apps/desktop/package.json`                            | `"version"`                        | 워크스페이스 패키지 이름표                                    |
| `packages/` 의 `ipc`·`ui`·`graph-view`·`diff-view`·`merge-editor`·`terminal` | 각 `package.json` 의 `"version"`   | 〃                                                            |
1. 위 11곳을 바꿉니다. 앱과 파일 이름에 실제로 쓰이는 것은 `tauri.conf.json` 이지만, 섞이지 않게 모두 맞춥니다.
2. 남은 곳이 없는지 저장소 루트에서 찾아봅니다. `version.workspace = true` 줄은 그대로 둡니다.

   ```bash
   rg -n '"version"|^version' --glob '*.json' --glob 'Cargo.toml'
   ```

3. `pnpm build` 처럼 cargo 를 부르는 명령을 한 번 실행하면 `Cargo.lock` 의 mgit crate 버전이 새 값으로 바뀝니다. 이 변경도 함께 commit 합니다.
4. `pnpm-lock.yaml` 에는 이 버전들이 적혀 있지 않습니다. 그래도 `pnpm install` 을 한 번 실행해 lock 이 바뀌지 않는 것을 보면, `pnpm install --frozen-lockfile` 로 설치할 때도 막히지 않습니다.
5. 빌드하면 파일 이름이 바뀝니다(예: `mGit_0.2.0_aarch64.dmg`). 이전 버전의 dmg 는 이름이 달라 덮어쓰지 않으므로 같은 폴더에 남아 있을 수 있습니다. 이름의 버전을 보고 고릅니다.
6. 만든 앱의 버전은 `plutil -p target/release/bundle/macos/mGit.app/Contents/Info.plist` 의 `CFBundleShortVersionString` 이나 Finder 의 정보 가져오기로 봅니다. 앱 화면에는 버전을 보여 주는 곳이 없습니다.

GitHub Releases 에 올릴 때는 태그 이름을 이 버전에 맞춥니다(8절).

## 8. 릴리스 올리기

저장소에는 GitHub Actions 워크플로가 없습니다. 릴리스는 이 Mac 에서 만든 dmg 를 GitHub Releases 에 손으로 올립니다.

> [!NOTE]
> 이 절의 절차는 아직 해 보지 않았습니다(확인 전). 예전에 있던 릴리스 워크플로(`build.yml`, tauri-action)는 한 번도 돈 적이 없어 테스트 워크플로(`ci.yml`)와 함께 지웠습니다. 공개 저장소에서는 GitHub 의 표준 러너가 무료이므로, Windows 판이 필요해지면 다시 붙입니다(9절).
1. 7절대로 버전을 올리고 commit 해 GitHub 에 push 합니다.
2. 2절(Intel Mac 도 쓰면 3절의 universal)대로 dmg 를 만듭니다.
3. 그 commit 에 태그를 달아 push 합니다. 태그는 `tauri.conf.json` 의 버전 앞에 `v` 를 붙인 것입니다.

   터미널에서는 다음과 같습니다.

   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```

   mGit 으로 해도 됩니다. 저장소 탭의 로그에서 그 commit 행을 우클릭해 **여기에 tag 만들기…** 로 `v0.1.0` 을 만들고, 브랜치 칸 **태그** 묶음에서 그 tag 를 우클릭해 `origin 로 push` 를 고릅니다([사용법 5.4](사용법/5-가끔-하는-작업.md#tag-push-하기)). 툴바 **Push** 는 tag 를 보내지 않습니다.

4. 그 태그로 초안 릴리스를 만들며 dmg 를 올립니다. 올라간 파일을 확인하고 GitHub 의 Releases 에서 게시(Publish)합니다. 초안은 게시하기 전까지 저장소에 쓰기 권한이 있는 사람만 봅니다.

   ```bash
   gh release create v0.1.0 target/release/bundle/dmg/mGit_0.1.0_aarch64.dmg --draft --title "mGit v0.1.0"
   ```

- 릴리스 이름은 태그에서, 파일 이름은 `tauri.conf.json` 의 버전에서 옵니다. 둘이 다르면 `mGit v0.2.0` 릴리스에 `0.1.0` 파일이 올라갑니다(10절).

## 9. Windows

Windows 판은 지금 만들지 않습니다. 이 Mac 에서는 만들 수 없고 CI 도 없습니다. 필요해지면 Windows 에서 직접 빌드하거나 GitHub Actions 를 다시 붙여 확인합니다. Windows 에서의 사용법은 이 문서들에서 다루지 않습니다.

- CI 를 지우기 전에 Windows 에서 컴파일과 clippy 는 통과했습니다. 테스트는 끝까지 돌려 보지 못했습니다(확인 전).
- 지금 `tauri.conf.json` 의 `bundle.targets` 는 `["app", "dmg"]` 로 macOS 형식만 적혀 있습니다. Windows 설치 파일(`msi`·`nsis`)을 만들려면 이 값도 바꿔야 할 수 있습니다(확인 전).

## 10. 문제 해결

### "확인되지 않은 개발자" 경고가 뜸

받은 Mac 에서 처음 열 때 뜨는 정상적인 경고입니다. Apple 이 악성 소프트웨어를 확인할 수 없다는 경고도 같습니다. [5절](#5-다른-mac-에서-열기)의 방법 1이나 2를 따릅니다.

### "손상되었기 때문에 열 수 없습니다" 류의 경고가 뜸

1. 서명이 깨졌는지 봅니다.

   ```bash
   codesign --verify --deep --strict /Applications/mGit.app
   ```

2. 아무것도 나오지 않고 끝나면(종료 코드 0) 서명은 멀쩡합니다. 격리 속성 때문이니 5절 방법 2로 지웁니다.
3. 오류가 나오면 옮기는 중에 파일이 바뀐 것입니다. dmg 를 다시 받아 설치합니다.

받은 Mac 이 Intel 인데 `aarch64` dmg 를 설치했어도 열리지 않습니다. universal dmg(3절)를 받습니다.

### 앱에 합성 데이터가 보임(목 모드가 들어간 앱)

상태 바의 git 버전에 `(mock)` 이 붙거나 탭 경로가 `/mock/…` 이면 목 모드로 빌드된 앱입니다. 빌드할 때 셸에 `VITE_MGIT_MOCK` 이 남아 있었던 것입니다.

1. `unset VITE_MGIT_MOCK VITE_MGIT_MOCK_SCENE` 으로 지웁니다.
2. `pnpm build` 로 다시 만들고 다시 설치합니다.
3. 그 dmg 를 이미 나눠 줬으면 새 dmg 로 바꿔 줍니다.

### 버전과 파일 이름이 맞지 않음

- dmg 이름과 앱 버전은 `tauri.conf.json` 의 `version` 에서 옵니다. `Cargo.toml`·`package.json` 만 바꾸면 이름은 그대로입니다. 7절의 11곳을 모두 바꿉니다.
- 릴리스 이름은 태그에서 옵니다. 태그와 `tauri.conf.json` 의 버전을 맞춥니다(8절).
- 폴더에 이전 버전 dmg 가 남아 있을 수 있습니다(7절 5).

### 빌드가 `beforeBuildCommand` 에서 실패함

``Running beforeBuildCommand `pnpm build:web` `` 다음에 오류로 끝나면 화면 빌드(vite)가 실패한 것이고 Rust 는 아직 시작하지 않았습니다. `pnpm check` 로 lint·typecheck·test 오류를 보고 고칩니다([빌드·테스트 5절](빌드-테스트.md#5-테스트와-검사)). 화면 빌드는 타입 검사를 하지 않으므로, 빌드가 됐더라도 나눠 주기 전에 `pnpm check` 를 돌립니다.

### 디스크 공간이 모자람

- release 빌드 결과는 `target/release/` 에 쌓입니다. 빈 `target/` 에서 한 번 빌드한 뒤 2.6GB 였습니다. 개발 실행·테스트가 쓰는 `target/debug/` 는 이보다 훨씬 큽니다([빌드·테스트 8절](빌드-테스트.md#8-문제-해결)).
- 자리가 모자라면 `cargo clean --release` 로 release 결과만 지웁니다. 만든 `.app`·`.dmg` 도 함께 지워지니 필요한 dmg 는 먼저 다른 곳에 옮깁니다. 다음 `pnpm build` 는 처음부터 컴파일합니다(2절 표의 1분 45초).
