# 폴더 작업 편의 구현 결과 — 전체 선택·작업 기록·자동 fetch 간격

기준: 브랜치 `feat/folder-batch-ux` · 2026-11-23 · 기준 커밋 `45dbbf5` · 계획 `plan/folder-batch-ux.md` (로컬 전용, 워크트리 `PLAN.md` 사본)

## 요약

사용자가 폴더 탭(멀티 레포)을 쓰다 겪은 불편 세 가지를 고쳤습니다.

1. **전체 선택·해제**: 여러 개를 고르는 체크 목록 7곳에 `전체 선택`·`전체 해제` 를 달았습니다.
   - 필터 막대의 저장소·branch·작성자 드롭다운
   - "대상 저장소 N개" 묶음이 있는 대화상자: push, checkout, 새 branch, 이름 바꾸기
2. **작업 기록**: 일괄 작업이 끝나면 개요 탭에 남던 결과 목록을 없앴습니다.
   - 끝나면 토스트로 요약합니다.
   - 저장소별 결과는 Git 도구 창의 새 **작업 기록** 탭에 끝난 시각과 함께 쌓입니다.
3. **자동 fetch 간격**: 저장소 탭에서만 5분 고정으로 돌던 자동 fetch를 바꿨습니다.
   - `⌘,` 설정에서 간격을 고릅니다(끔·5·10·15·30·60분, 기본 5분).
   - 폴더 탭에도 적용됩니다.
   - 백그라운드 fetch는 인증 대화상자를 띄우지 않습니다.

진행 방식은 팀장 모드였습니다.

- A(전체 선택)와 B(자동 fetch 백엔드·IPC)를 작업자 2명이 병렬로 맡았습니다.
- C(작업 기록·설정 화면·문서)는 A·B가 끝난 뒤 진행했습니다.
- 팀장은 단위마다 diff를 직접 검토하고 검증을 다시 돌린 뒤 커밋했습니다.

## 구현 내용

### A. 전체 선택·해제 (`83abd3e`)

공유 부품 두 곳만 고쳐 7개 목록에 모두 적용했습니다.

- **필터 드롭다운** (`apps/desktop/src/features/filter-bar/FilterDropdown.tsx`, `filter-model.ts`)
  - 단추는 검색 칸 아래에 있습니다.
  - 지금 보이는(검색으로 걸러진) 항목에만 적용합니다.
  - 초안만 바꾸고, 닫을 때 한 번 적용합니다. 지금까지와 같은 방식입니다.
  - 순수 함수
    - `checkShown`: branch의 HEAD는 다른 항목과 함께 고를 수 없으므로 더하지 않습니다. 체크돼 있던 HEAD는 뺍니다. 더할 항목이 없으면 그대로 둡니다(보이는 것이 HEAD뿐일 때 선택이 비지 않게).
    - `uncheckShown`: 보이는 항목의 체크만 뺍니다.
- **대화상자 묶음** (`packages/ui/src/PromptDialog.tsx`)
  - 단추가 생기는 조건
    - 켜진 체크 칸이 2개 이상인 묶음
    - 위험한 대화상자(`danger`)가 아닌 경우. 그래서 tag 지울 곳에는 생기지 않습니다.
  - 단추는 legend 밖에 두고 같은 줄 오른쪽에 그립니다. 끈 칸은 건드리지 않습니다.

### B. 자동 fetch (`dce12fd`)

- **간격**
  - `CoreInner.auto_fetch_ms`(밀리초, 0 = 끔)로 바꿨습니다.
  - `Core::set_auto_fetch_interval`은 열린 저장소 탭(Full 세션)과 폴더의 루프를 곧바로 다시 겁니다.
  - 간격 읽기와 태스크 보관은 한 잠금 구간(`rearm_auto_fetch`)에서 합니다. 그래서 열기·승격과 간격 변경이 겹쳐도 옛 간격의 루프가 남지 않습니다.
- **폴더 루프** (`crates/mgit-core/src/folder_auto_fetch.rs`)
  - 순번 묶음의 대표마다 fetch합니다.
  - 건너뛰는 저장소
    - 폴더 설정에서 뺀 저장소
    - 저장소 탭으로 열린 저장소(정규화한 `common_dir`로 판별)
    - 원격이 없는 저장소
    - 저장소 설정에 ssh 명령이 있는 저장소
  - 동시 실행 수는 폴더 설정을 따릅니다.
  - 원격 추적 ref가 바뀌었거나 실패한 저장소만 `folderAutoFetched`로 알립니다.
- **공통 절차** (`crates/mgit-core/src/auto_fetch.rs`)
  - 탭 루프와 폴더 루프가 함께 씁니다.
  - 공통 규칙: `--no-prune-tags`(TG-16), undo·Operation 없음, ssh 명령 건너뛰기, 묻지 않는 인증.
- **묻지 않는 인증**
  - `MGIT_HELPER_SILENT=1`을 붙인 명령은 키체인에 저장된 비밀만 받습니다.
  - 키체인에 없으면 대화상자 없이 실패합니다.
  - 사용자가 직접 누른 fetch는 지금처럼 묻습니다.
- **설정 저장**
  - `auto_fetch_get`·`auto_fetch_set`(분, 0~1440)을 더했습니다. SQLite `setting` 키 `autoFetch`에 저장합니다.
  - 앱 시작 시(`state.rs`) 이 값으로 코어를 만듭니다. 값이 없으면 5분입니다.

### C. 작업 기록 탭과 설정 화면 (`65ff30f`)

- **기록 저장** (`folder-store.ts`)
  - `batchResult`를 `taskHistory`로 바꿨습니다. 폴더 탭마다 100줄이고 메모리에만 둡니다.
  - 일괄 작업·일괄 commit의 성공·실패와 폴더 자동 fetch를 기록합니다.
  - 같은 실패만 이어지는 자동 fetch는 한 줄로 합칩니다(`repeat`).
- **작업 기록 탭**
  - Git 도구 창의 탭은 `로그 · 작업 기록 · 콘솔`입니다. 작업 기록은 폴더 탭에만 있습니다.
  - 저장소 탭에서는 그 탭 대신 로그를 그립니다. 홈은 지금처럼 숨깁니다.
- **개요 탭**
  - 결과 목록을 없앴습니다.
  - 다른 진입점처럼 `useBatchReport()`로 토스트를 띄웁니다.
- **설정 화면**: 설정 대화상자 맨 아래에 **자동 fetch 간격** select를 더했습니다. 값이 바뀌었을 때만 저장합니다.

## 계획과 달라진 점

- 폴더 루프는 저장소 탭 여부를 작업 트리가 아닌 `common_dir`로 판단합니다. 워크트리를 탭으로 열어도 같은 원격 추적 ref를 갱신하기 때문입니다.
- 간격을 밀리초로 저장합니다. 테스트가 밀리초 간격을 쓰기 때문입니다.
- 기존 테스트 `light_session.rs`를 조정했습니다.
  - 이 테스트는 폴더를 연 채 "fetch가 돌지 않는다"고 단언합니다. 이제 폴더 루프가 저장소를 fetch하므로 그대로는 실패합니다.
  - 해당 저장소를 폴더 설정 `exclude`로 빼서, 원래 의도인 "가벼운 세션 자체는 fetch하지 않는다"만 검사하게 했습니다.
- 필터 드롭다운의 단추는 Tab으로 갈 수 있습니다. 그래서 검색 칸에서 Tab을 누르면 팝오버가 닫히지 않고 전체 선택으로 갑니다.
- 실행하지 못한 일괄 작업은 코어 라벨이 없습니다. 그래서 라벨을 `S.folder.history.ops[op.kind]`에서 가져옵니다. `BatchOp` 종류가 늘면 타입 오류로 드러납니다.

## 알려진 한계 (수용)

- 폴더 자동 fetch 명령도 폴더 콘솔에 남습니다. 저장소 탭의 자동 fetch와 같은 동작입니다(A24).
- 같은 저장소가 열린 폴더 두 곳에 있으면 루프 두 개가 각각 fetch합니다. 쓰기 잠금 때문에 순서대로 돕니다.
- 폴더 루프는 `cfg.git_config_overrides`를 붙이지 않습니다. 수동 일괄 fetch와 같고, 데스크톱은 이 값을 비워 두어 실제 차이가 없습니다.
- 작업 기록의 라벨은 기록할 때의 언어로 남습니다.
- 저장소 탭에서 저장된 Git 탭이 `history`이면 '로그 보기' 동작이 이미 보이는 로그에 대해서도 저장 탭을 `log`로 바꿉니다. 숨기지는 않으므로 해가 없습니다.
- 문서의 설정 대화상자 캡처(`external-apps.png`)에는 새 select가 없습니다.

## 실기기 확인 목록 (사용자)

1. 저장소 필터 드롭다운에서 검색 → 전체 선택 → 닫기를 하면 보이는 저장소만 적용되는지 확인합니다.
2. 새 branch 대화상자에서 다음을 확인합니다.
   - 전체 해제를 하면 만들기 단추가 꺼지고, 전체 선택을 하면 켜지는지
   - 단추가 "대상 저장소 N개" 제목 줄 오른쪽에 서는지(WebKit에서는 아직 확인하지 않았습니다)
3. 일괄 fetch 뒤 개요에 목록이 남지 않는지, 토스트가 뜨는지, 작업 기록 탭에 시각과 저장소별 결과가 보이는지 확인합니다.
4. `⌘,`에서 자동 fetch 간격을 바꿔 봅니다.
   - 다른 클론에서 push한 뒤 폴더 탭의 마지막 fetch 시각, 작업 기록, 토스트가 바뀌는지 확인합니다.
   - 끔으로 바꾸면 멈추는지 확인합니다.
