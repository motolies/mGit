## 주요 판단과 근거

### 일괄 push 의 원격 선택(A)

- 업스트림이 없는 branch 는 origin 이 있으면 `push -u origin <branch>` 로 보냅니다.
- origin 이 없으면 push 체크 목록에서 저장소마다 원격을 고릅니다. 원격이 하나면 미리 골라 두고, 고르지 않으면 사유와 함께 건너뜁니다.
- 원격이 없거나 분리된 HEAD 면 건너뜁니다. 업스트림이 있으면 예전과 같습니다.
- 규칙은 순수 함수 `upstream_remote` 로 분리해 따로 테스트합니다. `newUpstream` 이 없는 호출(서브모듈 일괄 push)은 예전처럼 건너뜁니다.

### 일괄 작업 취소 범위(C)

- 시작하지 않은 저장소는 "취소됨" 으로 끝납니다.
- 이미 도는 명령은 **fetch·push 만** 끊습니다(저장소 탭 취소와 같은 SIGTERM → SIGKILL).
- pull·checkout·통합처럼 작업 트리를 바꾸는 명령은 끝까지 둡니다. 작업 트리를 바꾸는 도중에 끊지 않기 위해서입니다.
- 취소는 건너뜀·실패와 따로 셉니다(`RepoResult.cancelled`). 서브모듈 push 를 취소하면 상위 저장소 push 로 이어 가지 않습니다(`44428dd`).

### 실패한 저장소만 다시 실행(D)

- 작업 기록에 실행 인자(작업·대상)를 남깁니다.
- fetch·pull·branch 업데이트는 바로 다시 실행합니다. 확인 창이 있던 작업은 같은 확인 창을 그 저장소로 좁혀 이전 값으로 다시 엽니다.
- 원격 branch 삭제·강제 삭제·commit 은 다시 실행 대상에서 뺐습니다.

### 명령 실행은 git 하위 명령만(N)

- 명세 MR-14 는 "선택한 저장소에 임의의 git 명령"이고, 명세 7절은 셸 문자열 조합을 금지합니다. 그래서 **git 하위 명령을 셸 없이 인자 배열로** 실행합니다.
- 파이프·리디렉션·변수 같은 셸 문법은 입력에서 거부합니다. 강제 push·변경 버리기·ref 삭제·이력 다시 쓰기·외부 프로그램·다른 경로·알 수 없는 명령(별칭)은 실행 전에 한 번 더 확인합니다.
- 출력은 stdout 앞 1 MiB·stderr 끝 64 KiB 만 남기고 URL 자격 증명을 가립니다. 자격 증명이 든 명령은 최근 명령에 남기지 않습니다.
- `npm` 같은 셸 명령은 통합 터미널을 안내합니다. **셸 명령까지 넓히려면 명세 변경이 먼저 필요합니다**(사용자 판단 사항).

### 편집기 수정 이력·2초 검사(N6)

측정 뒤 기본값(현재 줄 수정 이력·변경 표시 켜짐)은 유지하고 비용이 큰 부분만 없앴습니다. 근거는 [N6 측정](#n6-측정)에 있습니다.

### UTF-8 이외 인코딩(R2)

- 감지 차례: BOM(UTF-8·UTF-16 LE/BE) → UTF-8 → EUC-KR(CP949) → Shift_JIS. 고른 인코딩은 그 인코딩으로만 읽습니다.
- **같은 인코딩으로 다시 쓴 바이트가 원본과 같을 때만 편집**합니다. 아니면 읽기 전용(`Lossy`)으로 까닭과 외부 편집기 단추를 보입니다. 저장할 때 그 인코딩으로 쓸 수 없는 글자가 있으면 실패합니다.
- revision 은 원문 바이트 해시입니다(UTF-8 은 예전과 같은 값). 1 MiB 상한은 인코딩한 바이트로 셉니다.
- 내용 검색과 여러 파일 바꾸기는 UTF-8 만 다룹니다(예전과 같음).
- `encoding_rs` 를 직접 의존성으로 더하고 `THIRD-PARTY-NOTICES.md` 에 encoding_rs(MIT)·WHATWG(BSD-3-Clause) 고지를 넣었습니다.

### 가상 그룹 모델(M)

- 같은 저장소 중복(정규 경로 + 장치·inode)과 중첩 멤버는 거부합니다. 워크트리와 원 저장소는 함께 넣을 수 있습니다.
- 사라진 멤버는 정의에 남기고 상태 `missing`·`notRepo` 로 보입니다. 로스터에서 빠져 일괄 작업 대상이 아닙니다. 대시보드에 "찾을 수 없는 저장소" 줄과 **위치 다시 지정…**·**빼기** 가 있습니다.
- 키는 `mgit-group:<id>`(탭·편집기 탭·최근 파일), 폴더 설정은 `folder:mgit-group:<id>`, 정의는 코어 설정 키 `groups`(`version: 1`) 입니다.

### 결정

1. **수정 이력(Blame):** 기본값(현재 줄 켜짐)은 유지하고 입력 중 재조회를 없앴습니다. 조회 결과를 CodeMirror `StateField` 에 두고 편집을 따라 줄을 옮깁니다(`annotations.ts` `mapBlame`, 고친 줄은 로컬 변경). 다시 조회하는 때는 파일 열기, HEAD 변경(branch·commit), 원문 교체, 새로고침, 설정 켜기뿐이고 자동 저장은 이유가 아닙니다. 바뀐 뒤 비용은 열기·commit 때 한 번 21~42ms(최악 702ms, UI 스레드 밖)입니다.
2. **변경 표시:** 입력마다 비교는 유지합니다(2만 줄·20곳에서 1~1.5ms). HEAD 원문은 1번과 같은 때만 다시 읽습니다.
3. **2초 검사:** 코어 `fs_file_stamps` 의 표지(경로·크기·mtime·dev·ino·mode·ctime 의 SHA-256)가 같으면 원문을 읽지 않습니다. 창 포커스는 모두 읽습니다(시각 정밀도가 낮은 파일 시스템의 안전망). 감시 이벤트도 표지를 먼저 봅니다.

- 가상 그룹 M4 판단 검토에서 받아들인 것: 위치를 바꾼 멤버의 파일 탭은 닫음, 코어가 고치기를 거부하면 닫은 탭을 되살리지 않음, 스토어가 `features/` 의 브랜치 즐겨찾기 모듈을 가져다 씀(계층 역방향).

- UTF-16 은 BOM 이 있어야 알아봅니다. 내용 검색·여러 파일 바꾸기는 UTF-8 만 다룹니다.
