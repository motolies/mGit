기준: 브랜치 `feat/tag-management` · 2026-11-23 · 계획 `agent-docs/태그-관리-기능-계획.md`

## 요약

- 앱 안에서 tag 를 모두 관리할 수 있게 했습니다.
  - push: 하나·여럿·모든 tag
  - 지우기: 로컬만·원격별·둘 다
  - 원격 상태 확인: 로컬에만·원격에만·같음·다름
  - 원격 tag 가져오기, 정리, 다름 해소
  - 에디터의 "태그" 문서
- 병렬 레인 3개(R 코어·IPC, U 화면, D 벤치·명세)로 진행했고, 팀장이 동기화 지점 H1~H4 에서 병합·검증했습니다.
- 사용설명서는 Phase M 에서 종합 업데이트했습니다(5.4 tag 절 전면 개편, 3·4·6·7·9·10장, 목차, README, 패키징, 빌드-테스트, 그림 5장 추가와 1장 갱신).
- 사용자 요청으로 `master` 에 병합했습니다(병합 커밋 `6a5627a`, 부모 `c92ae32`·`d499139`, 트리는 통합 브랜치와 같음). 원격 push 는 하지 않았습니다.

## 계획과 달라진 점 (실행 중 결정 E1~E16 요약)

자세한 내용은 계획 문서의 "실행 중 결정·관문 결과" 표에 있습니다.

- **원격 삭제는 확인 전에는 아무것도 지우지 않습니다**(E1, `notRun`). [취소] 가 실제로 취소가 되게 하기 위해서입니다.
- **다름 확인은 콜백과 `confirmChoice`** 로 합니다(E2). 계획의 PendingHint 방식은 "확인 중 busy 유지"와 함께 성립하지 않았습니다.
- **"로컬 것으로 맞추기"는 lease push 한 번**입니다(E8, `replaceRemoteTags`). 삭제 → push 두 단계 사이의 일부 성공 상태를 없앴습니다.
- **단일 조회 패턴은 4개 이하일 때만** 씁니다(E11, B4 실측).
- **보고서 크기 기준 초과는 받아들였습니다**(E9). 5만 tag 에서 3.5MB 지만 시간은 24ms 입니다.
- **대량 일괄 작업에는 500개 이상일 때 시간 안내**를 보입니다(E15).
- **기존 단건 `deleteTag` 경로를 제거**했습니다(E14).
- **트리 다시 그리기 비용을 줄였습니다**(E13). 로컬 삭제 한 번에 3회 → 2회, 380ms 대 → 300ms 대(tag 3,000, 개발 빌드).

## 실기기 확인 목록 (사용자)

목 모드와 로컬 bare 원격으로는 확인할 수 없는 것입니다.

- [ ] HTTPS 원격: askpass·키체인 창이 청크·조회마다 반복해서 뜨지 않는지
- [ ] SSH 원격에서 push·원격 삭제·원격 확인
- [ ] GitHub 보호 tag 규칙으로 거부될 때 "서버가 거부함: 사유" 문구
- [ ] tag 1천 개 이상 실제 저장소에서 원격 확인 시간과 태그 문서 반응

- [ ] 브랜치 칸에서 키보드 커서가 있는 tag 행의 툴팁(목에서 한 번 비어 보였고 재현되지 않음)
