## 7.1 같은 조작, 탭·자리마다 다른 뜻

폴더 탭과 저장소 탭은 화면 틀이 같지만, 같은 조작이 다른 일을 할 때가 있습니다.

| 조작                                | 폴더 탭                                       | 저장소 탭                                               | 자세히                                                                      |
| ----------------------------------- | --------------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| 브랜치 칸에서 branch 클릭           | 로그를 그 branch 로 거름                      | 로그에서 그 commit 으로 이동                            | [4.4](4-일상-작업.md#브랜치-칸)                                             |
| 브랜치 칸에서 branch 더블클릭·Enter | 저장소 체크 목록을 띄워 checkout              | 확인 없이 바로 checkout. 태그면 분리된 HEAD 로 checkout | [4.4](4-일상-작업.md#브랜치-칸), [5.4](5-가끔-하는-작업.md#보기와-checkout) |
| Commit 도구 창에서 파일 한 번 클릭  | diff 탭으로 엶                                | 고르기만 함. 더블클릭·Enter 로 엶                       | [4.1](4-일상-작업.md#41-변경-확인하기)                                      |
| 상세 칸에서 변경 파일 열기          | 파일마다 탭(클릭은 미리보기, 더블클릭은 고정) | 저장소마다 탭 하나. 다른 파일을 열면 내용이 바뀜        | [3.5](3-화면-둘러보기.md#탭-종류)                                           |
| `⌘F`                                | 필터 바의 텍스트 칸으로                       | 찾기 줄을 엶                                            | [9.1](9-단축키.md#로그에서-찾기거르기)                                      |
| `⌘⇧G`                               | 필터 바의 첫 드롭다운(**저장소**)으로         | 필터 바의 텍스트 칸으로                                 | [9.1](9-단축키.md#로그에서-찾기거르기)                                      |
| pull 방식                           | 폴더 설정에서 정함(처음 ff-only). 저장됨      | 툴바 **Pull** 옆 선택 상자. 탭을 다시 열면 처음 값으로  | [4.3](4-일상-작업.md#43-fetchpullpush-하기)                                 |
| 충돌이 생겼을 때                    | 작업 진행 띠에 그 저장소 줄만 생김            | Commit 도구 창의 **변경** 탭이 저절로 열림              | [5.6](5-가끔-하는-작업.md#폴더-탭과-저장소-탭의-차이)                       |
| 콘솔에 쌓이는 명령                  | 쓰기·네트워크 명령만                          | 이 저장소의 명령 전부                                   | [3.9](3-화면-둘러보기.md#39-콘솔과-터미널)                                  |

탭 종류가 아니라 포커스나 누른 자리에 따라 달라지는 것도 있습니다.

| 조작            | 경우                                | 결과                                                   | 자세히                                                        |
| --------------- | ----------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------- |
| `⌘W`            | 편집기에 포커스가 있음              | 편집기 탭 하나를 닫음. 닫을 탭이 없으면 아무 일도 없음 | [2.7](2-저장소와-폴더-열기.md#27-탭-오가기와-닫기)            |
| `⌘W`            | 그 밖(Project 트리·로그·도구 창 등) | 폴더·저장소 탭 전체를 닫음                             | [2.7](2-저장소와-폴더-열기.md#27-탭-오가기와-닫기)            |
| 저장소 더블클릭 | 개요 표의 줄                        | 저장소 탭으로 엶                                       | [3.6](3-화면-둘러보기.md#36-개요-탭)                          |
| 저장소 더블클릭 | Project 트리의 저장소 행            | 펼치기만 함. 탭은 우클릭 → **저장소 탭으로 열기**      | [2.2](2-저장소와-폴더-열기.md#폴더-탭에서-저장소-탭으로-열기) |
| Esc             | 미리보기·diff·충돌 편집기 탭        | 그 탭을 닫음                                           | [9.1](9-단축키.md#esc-가-닫는-순서)                           |
| Esc             | 고정 탭·개요 탭                     | 닫히지 않음. `⌘W` 나 × 로 닫음                         | [9.1](9-단축키.md#esc-가-닫는-순서)                           |
| Space           | 폴더 탭 Commit 도구 창의 행         | 체크를 켜고 끔. 누르는 즉시 stage·unstage 됨           | [4.1](4-일상-작업.md#폴더-탭에서는)                           |
| Space           | Project 트리의 파일                 | 미리보기 탭으로 엶                                     | [3.4](3-화면-둘러보기.md#조작)                                |

## 7.2 확인 없이 바로 바뀌는 것

아래 동작은 확인창 없이 바로 git 상태나 파일을 바꿉니다. 이미 실행했다면 [7.3](#73-되돌리기의-한계)과 [6장](6-실수했을-때.md)을 보세요.

| 증상                                                                        | 이유                                                                                                                                                        | 피하거나 되돌리는 법                                                                           | 자세히                                                                                             |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 폴더 탭 Commit 도구 창에서 체크했더니 hunk 단위로 골라 둔 stage 가 사라졌다 | 체크 상자는 누르는 즉시 git index 를 바꿉니다. 일부만 stage 된(가로줄) 파일을 누르면 파일 전체가 stage 됩니다                                               | 그런 파일은 폴더 탭에서 누르지 말고 저장소 탭에서 다룹니다                                     | [4.2](4-일상-작업.md#체크-상자의-뜻)                                                               |
| 폴더 탭 commit 에 생각보다 많은 파일이 들어갔다                             | stage 된 것을 전부 commit 합니다. 터미널 등 앱 밖에서 stage 해 둔 것도 함께 들어갑니다                                                                      | **Commit** 전에 `저장소 N개 · 파일 M개` 를 확인합니다                                          | [4.2](4-일상-작업.md#폴더-탭에서-stage-하고-commit-하기)                                           |
| 폴더 탭 툴바 **Fetch**·**Pull** 이 여러 저장소에 바로 실행됐다              | 확인 없이 고른 저장소에 실행합니다. 저장소 행을 고르지 않았거나 파일만 골랐으면 전체가 대상입니다                                                           | 단추에 마우스를 올려 `Fetch (선택 2개)` 꼴의 대상 수를 확인합니다                              | [4.3](4-일상-작업.md#폴더-탭에서는-일괄-실행)                                                      |
| 폴더 탭 일괄 Pull 로 여러 저장소가 rebase 됐다                              | 폴더 설정의 **일괄 pull 방식** 이 **rebase** 입니다                                                                                                         | 처음 값 **ff-only (안전)** 는 이력을 바꾸지 않습니다                                           | [4.3](4-일상-작업.md#43-fetchpullpush-하기), [8.8](8-설정.md#88-폴더-설정)                         |
| 저장소 탭 **Push** 가 바로 나갔다. 원격에 같은 이름의 branch 가 새로 생겼다 | 확인창이 없습니다. 업스트림이 없으면 같은 이름으로 보내고 업스트림으로 지정합니다                                                                           | 보내기 전에 툴바 배지(`↑2 ↓0`)와 **Push** 툴팁의 대상을 확인합니다                             | [4.3](4-일상-작업.md#43-fetchpullpush-하기)                                                        |
| `origin/x` 같은 원격 branch 가 사라졌다                                     | Fetch 는 자동 fetch 를 포함해 늘 `--prune` 으로 실행합니다. 원격에서 지워진 branch 는 내 저장소에서도 정리됩니다                                            | 그 branch 를 추적하던 로컬 branch 는 남고 **원격 삭제됨** 으로 표시됩니다                      | [4.3](4-일상-작업.md#43-fetchpullpush-하기)                                                        |
| `⌘⇧S` 를 눌렀더니 바로 stash 됐다. untracked 파일도 치워졌다                | 팔레트의 **stash 저장** 은 대화상자 없이 untracked 까지 넣습니다                                                                                            | 메시지·옵션을 고르려면 Stash 탭의 **stash 저장…** 을 씁니다                                    | [3.11](3-화면-둘러보기.md#311-커맨드-팔레트), [4.7](4-일상-작업.md#47-stash-하기)                  |
| 메뉴에서 고르자마자 merge·rebase·cherry-pick·revert·reset 이 실행됐다       | 로그 행·브랜치 칸 메뉴의 이력 작업 대부분, 미리보기의 실행 단추, 격리 병합의 **메인에 반영** 은 확인창이 없습니다. 확인창은 hard reset 등 일부에만 있습니다 | 먼저 미리보기로 결과를 봅니다. 잘못했으면 탭을 닫기 전에 ↶ **되돌리기**(`⌘Z`)를 누릅니다       | [5.1](5-가끔-하는-작업.md#백업이-만들어지는-작업), [6.1](6-실수했을-때.md#61-undoredo-로-되돌리기) |
| **규칙 적용** 이 충돌 파일을 덮어쓰고 해결로 표시했다                       | 확인 없이 규칙대로 덮어쓰고 stage 합니다. **명령 실행** 규칙은 셸 명령을 그대로 실행합니다                                                                  | 적용하기 전에 **규칙…** 에서 glob 과 명령을 확인합니다                                         | [5.6](5-가끔-하는-작업.md#경로별-해결-규칙)                                                        |
| **ignore 에 추가** 로 `.gitignore` 가 바로 바뀌었다                         | 확인 없이 파일 끝에 줄을 붙이고, ↶ **되돌리기** 대상도 아닙니다                                                                                             | `.gitignore` 를 열어 그 줄을 지웁니다                                                          | [4.2](4-일상-작업.md#ignore-에-추가하기)                                                           |
| **업스트림 해제** 나 **백업 삭제** 가 바로 됐다                             | 두 항목은 확인창이 없습니다                                                                                                                                 | 업스트림은 **업스트림 지정…** 으로 다시 정합니다. 백업은 지우기 전에 한 번 더 봅니다           | [4.4](4-일상-작업.md#업스트림-지정해제), [6.2](6-실수했을-때.md#62-백업에서-되살리기)              |
| **사라진 워크트리 정리** 를 눌렀더니 바로 정리됐다                          | 단추 툴팁은 `… — 정리할까요?` 이지만 확인창 없이 실행합니다                                                                                                 | 폴더가 없는 워크트리의 기록만 지우므로, 폴더를 잠깐 옮겨 둔 것이면 누르기 전에 되돌려 놓습니다 | [5.7](5-가끔-하는-작업.md#잠금과-정리)                                                             |
| **Continue**·**Skip** 이 바로 진행됐다                                      | 작업 진행 띠에서 확인창은 **Abort** 에만 있습니다. **Skip** 은 그 commit 을 건너뛰고 그 파일의 저장하지 않은 편집도 버립니다                                | **Skip** 전에 그 commit 이 필요 없는지 확인합니다                                              | [5.6](5-가끔-하는-작업.md#작업-진행-띠)                                                            |

## 7.3 되돌리기의 한계

툴바의 ↶ **되돌리기**(Undo)와 백업·폐기 백업·reflog 로 많은 것을 되돌릴 수 있지만, 되돌릴 수 없는 것도 있습니다.

| 증상                                                         | 이유                                                                                                                                    | 피하거나 되돌리는 법                                                                                                                           | 자세히                                                                                                                                              |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| ↶ **되돌리기** 를 했는데 파일은 그대로다. 변경이 잔뜩 생겼다 | Undo 는 branch·tag·HEAD 의 위치만 되돌리고 작업 트리·stage 는 그대로 둡니다. checkout 을 되돌리면 두 branch 의 차이가 변경으로 보입니다 | 필요 없는 변경은 확인한 뒤 버리거나 stash 합니다                                                                                               | [6.1](6-실수했을-때.md#61-undoredo-로-되돌리기), [4.4](4-일상-작업.md#branch-바꾸기checkout)                                                        |
| ↶ **되돌리기** 가 없거나 꺼져 있다                           | 폴더 탭에는 없습니다. 탭을 닫거나 앱을 다시 켜면 기록이 사라집니다                                                                      | 백업이나 reflog 로 찾습니다                                                                                                                    | [6.2](6-실수했을-때.md#62-백업에서-되살리기), [6.4](6-실수했을-때.md#64-reflog-로-찾기), [2.8](2-저장소와-폴더-열기.md#28-다시-켰을-때-돌아오는-것) |
| 원격에서 지운 branch 가 되돌아오지 않는다                    | **원격에서 삭제…** 는 원격 저장소의 branch 를 지웁니다. 앱의 백업과 Undo 로 되살릴 수 없습니다                                          | 지운 commit 이 내 로컬 branch 에 있으면 그 branch 를 다시 push 합니다                                                                          | [4.4](4-일상-작업.md#원격에서-지우기)                                                                                                               |
| 지운 stash 를 되살리고 싶다                                  | **drop…** 한 stash 는 앱에서 되살릴 수 없고, stash 는 Undo 대상도 아닙니다                                                              | 지우기 전에 상세에서 내용을 확인합니다                                                                                                         | [4.7](4-일상-작업.md#applypopdrop)                                                                                                                  |
| 버린 변경을 되살리고 싶다                                    | 변경 영역 **되돌리기**·**hunk 되돌리기** 로 버린 것은 commit 된 적이 없어 git 으로도 Undo 로도 되찾을 수 없습니다                       | 버리기 직전 사본이 폐기 백업에 남습니다                                                                                                        | [4.2](4-일상-작업.md#변경-버리기), [6.3](6-실수했을-때.md#63-버린-파일-되살리기)                                                                    |
| hard reset 뒤에 작업 중이던 변경이 없다                      | **hard (변경을 모두 버림)** 가 버린 작업 트리 변경은 백업에도 Undo 에도 없습니다                                                        | hard reset 전에 commit 하거나 stash 합니다                                                                                                     | [5.1](5-가끔-하는-작업.md#reset)                                                                                                                    |
| 워크트리를 지웠더니 그 안의 변경도 사라졌다                  | 커밋하지 않은 변경이 있어도 강제로 지웁니다                                                                                             | 지우기 확인창의 문구를 읽고, 먼저 그 워크트리에서 commit 하거나 stash 합니다                                                                   | [5.7](5-가끔-하는-작업.md#57-워크트리)                                                                                                              |
| merge·cherry-pick·revert·reset soft 의 백업이 없다           | 이 작업들은 실행 전에 백업을 만들지 않습니다                                                                                            | 탭을 닫기 전이면 Undo, 아니면 reflog 에서 그 전 commit 을 찾아 branch 로 만듭니다                                                              | [5.1](5-가끔-하는-작업.md#백업이-만들어지는-작업), [6.4](6-실수했을-때.md#64-reflog-로-찾기)                                                        |
| 백업 묶음이 계속 길어진다                                    | 지난 백업을 지우는 정리가 실행되지 않아, 백업은 지울 때까지 남습니다                                                                    | 필요 없는 백업은 우클릭 → **백업 삭제** 로 지웁니다(확인 없이 바로 지워짐). 남겨 둘 시점은 **새 branch 로 복원…** 으로 branch 를 만들어 둡니다 | [6.2](6-실수했을-때.md#62-백업에서-되살리기)                                                                                                        |

## 7.4 폴더 탭에서 안 되는 것·다르게 되는 것

| tag 여러 개의 push·원격 삭제가 오래 걸린다                                 | git 이 보낼 tag 마다 로컬과 원격의 ref 전부를 견주어서, 고른 tag 가 많을수록, 원격에 tag 가 많을수록 느려집니다(tag 1만 개인 저장소에서 1천 개에 약 8초)             | 500개 이상이면 **tag 가 많아 몇 분 걸릴 수 있습니다. 진행 중에 취소할 수 있습니다.** 가 보입니다. 도는 동안 툴바의 ×(툴팁 **취소**)로 멈출 수 있고, 결과를 모르게 된 tag 는 **원격 tag 확인** 으로 다시 봅니다 | [5.4](5-가끔-하는-작업.md#모든-tag-push-하기)                                                          |
| tag 를 push 했더니 원격에 이름이 같은 다른 tag 가 있다며 거부됐다          | 원격에 같은 이름의 다른 tag 가 있습니다. 같은 commit 을 가리켜도 경량·annotated 가 다르면 다른 tag 입니다. 아무것도 바뀌지 않았습니다                                | 원격 것을 받으려면 태그 문서에서 **원격 것으로 맞추기…**, 원격을 바꾸려면 안내의 **원격 tag 를 로컬 것으로 덮어쓰기…**(되돌릴 수 없음)                                                                         | [5.4](5-가끔-하는-작업.md#원격과-다른-tag-맞추기)                                                      |
| `서버가 거부함: <사유>` 이 떴다                                            | 원격 저장소의 hook·보호 규칙이 거부했습니다. 강제 push 로도 풀리지 않습니다                                                                                          | 사유를 읽고 원격 저장소의 규칙을 확인합니다                                                                                                                                                                    | [10.9](10-문제-해결.md#tag-작업이-거부되거나-실패했을-때)                                              |
| `fetch.pruneTags` 를 켰는데 자동 fetch 가 원격에 없는 tag 를 지우지 않는다 | 의도된 동작입니다. push 하지 않은 tag 를 모르는 사이에 지우지 않도록 자동 fetch 는 tag 를 정리하지 않습니다                                                          | 직접 **Fetch** 하면 설정대로 정리합니다(늘 `--prune`). 이때 push 하지 않은 로컬 tag 도 지워지니 먼저 push 하세요                                                                                               | [4.3](4-일상-작업.md#자동-fetch와-배지)                                                                |
| tag 를 push 했더니 아직 올리지 않은 commit 도 함께 올라갔다                | tag 가 가리키는 commit 과 그 앞의 commit 중 원격에 없는 것은 함께 보내야 원격에 tag 가 생깁니다(git 동작)                                                            | push 하기 전에 그 commit 이 원격 branch 에 있는지 로그에서 확인합니다                                                                                                                                          | [5.4](5-가끔-하는-작업.md#tag-push-하기)                                                               |
| 첫 서브모듈을 화면에서 더할 수 없다                                        | ⋮ 단추는 서브모듈·모듈이 하나라도 있을 때만 보입니다                                                                                                                 | 터미널에서 `git submodule add <URL> <경로>` 를 씁니다                                                                                                                                                          | [5.8](5-가끔-하는-작업.md#한계)                                                                        |
| GitHub·GitLab 이 아닌 원격에도 **Pull Requests** 단추가 보인다             | 계정이 없으면 호스트 이름에 `gitlab` 이 없을 때 GitHub 로 짐작합니다                                                                                                 | 그런 원격에서는 도구 창을 쓰지 않습니다                                                                                                                                                                        | [5.9](5-가끔-하는-작업.md#보이는-조건)                                                                 |
| 계정을 연결하거나 원격을 바꿨는데 Pull Requests 도구 창이 그대로다         | 원격과 계정은 탭을 열 때만 읽습니다                                                                                                                                  | 그 저장소 탭을 닫고 다시 엽니다                                                                                                                                                                                | [10.8](10-문제-해결.md#108-pull-requests-에-계정이-없다고-나올-때)                                     |
| 툴바 툴팁의 `⌘R`·`⌘J` 가 바꾼 단축키와 다르다                              | 이 두 툴팁은 고정 글자입니다                                                                                                                                         | 팔레트의 키 표시를 봅니다                                                                                                                                                                                      | [9.2](9-단축키.md#저장과-반영)                                                                         |
