# UI 가독성 가이드

작성 기준: 2026-11-24, `ac54538` — 앱 전반 UI 가독성 및 설정창 스크롤 개선.

이 문서는 mGit의 화면을 추가하거나 수정하는 개발자와 에이전트가 참고하는 유지보수 기준입니다. **현재 정보 밀도를 유지하면서 제목·그룹·컨트롤의 구분을 강화합니다.** 화면 전체를 확대하기보다 요소의 역할에 맞춰 크기·색상·굵기·여백을 조정합니다.

## 1. 작업 전에 확인할 것

1. 바꾸는 요소가 제목, 그룹, 조작 요소, 데이터 행, 보조 설명 중 무엇인지 구분합니다.
2. [공통 토큰](../packages/ui/src/tokens.css)과 해당 화면의 CSS Module을 함께 읽습니다. 공통 토큰만 바꿔도 고정 크기 선언까지 바뀌지는 않습니다.
3. 아래 기준을 적용하고 다크·라이트, 한국어·영어, 최소 창 크기를 확인합니다.
4. 공통 기준을 바꾸면 소비 화면과 대비 테스트를 함께 검토하고 이 문서도 갱신합니다. 아래 값은 기준 커밋의 값이며, 이후 코드와 다르면 실제 구현과 변경 이유를 확인합니다.

## 2. 글자·크기·정보 위계

| 역할                  | 기준                                   | 적용 방법                                                                                             |
| --------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 기본 UI 본문          | `--font-size`: 13px                    | 새로운 일반 폼·본문의 기본값으로 사용합니다. 기존 조밀한 데이터 목록의 12px를 일괄 확대하지 않습니다. |
| 대화상자 제목         | `--font-size-title`: 16px, 굵기 600    | 창의 목적을 가장 먼저 식별할 수 있게 합니다.                                                          |
| 패널·섹션 제목        | `--font-size-section`: 13px, 굵기 600  | `--fg`를 사용합니다. 그룹은 배경과 여백도 구분합니다.                                                 |
| 메뉴·팝오버 그룹      | `--font-size-small`: 12px, 굵기 600    | 좁은 메뉴에서도 제목에 보조색을 사용하지 않습니다.                                                    |
| 설명·주요 안내        | `--font-size-small`: 12px              | `--fg-muted`를 사용합니다. 의미를 읽어야 하는 설명이 10px로 축소되지 않게 합니다.                     |
| 일반 버튼             | `--control-h`: 28px, 글자 13px         | 공용 `Button`의 기본 크기를 사용합니다.                                                               |
| 조밀한 도구 영역      | `--control-h-compact`: 24px, 글자 12px | `Button size="compact"`를 사용합니다.                                                                 |
| 대화상자 단일 행 입력 | `--field-h`: 32px, 글자 13px           | 입력·선택창의 최소 높이로 사용합니다. 다중 행 입력은 별도로 높이를 정합니다.                          |

부차적인 배지·카운터는 기존 작은 크기를 유지할 수 있습니다. `<small>`은 브라우저 기본 스타일로 더 작아지므로 주요 설명에는 글자 크기를 명시합니다. 아이콘과 트리 내부 액션은 기존 행 높이 안에 들어가도록 유지합니다.

### 그룹 제목

설정의 Sync·Branch처럼 여러 액션을 묶는 제목은 `--fg`, 굵기 600, `--bg-group` 배경을 함께 사용합니다. 색만 바꾸지 않고 여백으로도 구획을 구분합니다. 제목 자체에 동작이 없다면 hover나 버튼 테두리를 붙이지 않습니다. 실제 접기·펼치기 그룹은 기존 상호작용을 유지합니다.

[단축키 설정 스타일](../apps/desktop/src/features/app/ShortcutsDialog.module.css)의 그룹은 줄 높이 20px, 안쪽 여백 6px 10px, 바깥 여백 12px 0 4px를 사용합니다. 이 여백은 넓은 설정 목록의 예시입니다. 메뉴에는 더 작은 여백을 적용하고, 가상 트리 그룹은 기존 22px 행 안에서 글자색과 굵기로 구분합니다.

## 3. 색상과 상태

| 토큰               | 용도                             | 라이트 / 다크         |
| ------------------ | -------------------------------- | --------------------- |
| `--bg-group`       | 그룹 제목·표 머리의 중립 배경    | `#eceff5` / `#30343b` |
| `--control-border` | 일반 버튼·입력창을 식별하는 경계 | `#818895` / `#79818f` |
| `--border`         | 구분선·장식 경계·비조작 표시     | `#d9dce3` / `#393b40` |
| `--fg`             | 본문·제목·선택 위 글자           | `#1c1f26` / `#dfe1e5` |
| `--fg-muted`       | 보조 설명                        | `#646b79` / `#969aa2` |

색상 값은 공통 토큰에 정의하고 화면 CSS에서는 토큰을 참조합니다. 새 색 토큰은 두 테마에 모두 정의합니다. 컨트롤을 잘 보이게 하려고 모든 구분선을 함께 진하게 만들지 않습니다.

- 주요 버튼은 `--accent-fill`과 `--accent-fg`를 사용합니다. 글자 강조는 `--accent-text`를 사용합니다.
- 활성 도구 버튼은 `--bg-selected` 배경, `--fg` 글자, `--accent-text` 내부 강조선을 사용합니다. `aria-pressed` 등 실제 상태와 연결합니다.
- hover, 선택, 비포커스 선택, 활성 토글, disabled, 키보드 포커스를 구별합니다. 기존 선택 행의 상태색을 본문색으로 바꾸는 규칙도 유지합니다.
- `all: unset`을 사용하는 버튼은 포커스 표시를 다시 정의합니다. 채운 주요 버튼의 포커스 링은 배경에 묻히지 않도록 바깥에 표시합니다.
- 오류·충돌은 색 외에 문구·아이콘·굵기 등으로도 전달합니다. 파일 상태·브랜치·그래프의 의미 색상을 장식 목적으로 바꾸지 않습니다.

### 실제 조합의 대비 검증

텍스트는 4.5:1, 식별에 필요한 컨트롤 경계·아이콘·포커스 표시는 3:1을 검사합니다. disabled는 기존 대비 테스트의 예외로 취급하지만 활성 상태와 구분되어야 합니다. 장식용 구분선까지 일괄 3:1로 만들지는 않습니다.

[대비 표 테스트](../packages/ui/src/__tests__/contrast-table.test.ts)에 **실제로 함께 표시되는 전경색과 배경색**을 등록합니다. 기본 배경에서 통과해도 hover·선택·그룹 배경에서 실패할 수 있습니다.

이번 개선에서 확인한 사례입니다.

- 다크의 `--accent / --bg-selected`는 2.29:1이므로 활성 도구 버튼 내부 강조선은 `--accent-text`로 변경했습니다.
- 라이트 그룹 배경의 초기 후보 `#e9edf3`는 `--danger` 글자와 4.46:1이어서 최종값을 `#eceff5`로 조정했습니다.
- 새 그룹 배경에 `--fg-muted`를 사용하는 조합은 자동으로 보장되지 않습니다. 그룹 제목에는 `--fg`를 사용합니다.

## 4. 구현 시 유지할 계약

### 공용 버튼과 주변 컨트롤

[Button](../packages/ui/src/Button.tsx)은 `variant="primary" | "secondary"`, `size="default" | "compact"`를 지원합니다. 기본값은 secondary·default입니다. 화면별 CSS로 크기를 중복 정의하기 전에 이 API를 사용합니다. Push 같은 분할 버튼은 옆의 화살표·선택창 높이도 함께 맞춥니다.

[작업 진행 띠](../apps/desktop/src/features/workspace/OpBand.module.css)는 compact 버튼을 사용하면서 최소 행 높이와 스크롤 상한 계산을 37px 기준으로 맞춥니다. 공용 버튼 높이를 변경할 때 이런 부모의 고정 높이·상한 계산도 확인합니다.

### 목록 밀도와 가상화

| 영역        | 유지 기준                       | 크기를 바꿀 때 함께 확인할 코드                                                                   |
| ----------- | ------------------------------- | ------------------------------------------------------------------------------------------------- |
| 가상 트리   | `--tree-row-h`: 22px            | [use-virtual-tree.ts](../apps/desktop/src/components/use-virtual-tree.ts)의 토큰 읽기·기본값·측정 |
| 커밋 그래프 | `--row-h` 및 기본 행 높이: 24px | [GraphView.tsx](../packages/graph-view/src/GraphView.tsx)의 가상화·Canvas·키보드 이동             |
| 파일 내용   | `LINE_H`: 20px                  | [FileView.tsx](../apps/desktop/src/features/workspace/FileView.tsx)의 행 높이·위치 계산           |
| Diff        | 행 추정 높이: 20px              | [DiffView.tsx](../packages/diff-view/src/DiffView.tsx)의 가상화와 실제 행 스타일                  |

이 값은 가독성 개선을 이유로 일괄 확대하지 않습니다. 별도 밀도 변경 작업에서는 CSS와 가상화 계산을 함께 수정하고 스크롤 복원·키보드 탐색을 검증합니다. 병합 편집기와 터미널의 글꼴·행간 역시 독립 설정이므로 전역 CSS로 확대하지 않습니다.

### 대화상자와 좁은 화면

[설정 폼](../apps/desktop/src/features/app/AppDialogs.tsx)은 높이가 제한된 flex 구조에서 제목·탭·검색·하단 액션을 유지하고 본문 목록만 스크롤되게 합니다. 축소되는 중간 컨테이너에 `min-height: 0`을 지정하고, footer에는 `flex-shrink: 0`을 적용합니다. `overflow: hidden`만 추가해 내용이나 버튼을 숨기는 것으로 해결하지 않습니다. 숨겨진 탭 패널이 `display: flex` 규칙 때문에 다시 나타나지 않도록 `[hidden]`도 확인합니다.

최소 지원 창은 960×600입니다. [상단 툴바](../apps/desktop/src/layout/Toolbar.module.css)는 1100px 이하에서 간격·글자를 조정하고 필요한 경우 가로 스크롤을 허용합니다. 스크롤은 컨트롤이 사라지지 않게 하는 수단이며, 문서 탭과 테마 선택까지 접근 가능한지 확인합니다.

저장소 루트에서 실행하는 대표 검증 명령입니다. 변경에 맞는 기존 기능 테스트를 함께 실행합니다. 단순 CSS 수치를 그대로 복제하는 테스트는 추가하지 않습니다.

```bash
pnpm exec vitest run packages/ui/src/__tests__/tokens.test.ts packages/ui/src/__tests__/contrast-table.test.ts apps/desktop/src/__tests__/settings-dialog.test.tsx apps/desktop/src/__tests__/shortcut-settings.test.tsx
```

공용 스타일처럼 영향이 넓은 변경은 `pnpm test`로 전체 회귀를 확인합니다. 브라우저 확인은 [빌드·테스트 문서의 목 모드](../docs/빌드-테스트.md#4-목-모드--코어-없이-화면만-보기)를 사용합니다. 저장소·폴더·충돌 장면은 각각 `repo`, `folder`, `conflict`입니다.

```bash
VITE_MGIT_MOCK=2000 VITE_MGIT_MOCK_SCENE=repo pnpm -F @mgit/desktop dev:web
```

서버는 `http://localhost:1420`에서 실행됩니다. 실제 Git 쓰기 작업 없이 합성 데이터로 확인합니다. Chromium 확인만으로 macOS 앱의 WKWebView·네이티브 선택창까지 검증했다고 판단하지 않습니다.

## 7. 공통 키보드·탐색 규칙

- Tab과 Shift+Tab은 영역·컨트롤 그룹 사이를 이동합니다. 목록·트리·탭·단추 그룹의 각 항목을 모두 Tab 순서에 넣지 않습니다.
- 방향키는 현재 그룹 안에서 이동합니다. 트리·긴 목록은 양끝에서 멈추며 탭·짧은 도구 모음은 기존 순환 동작을 사용합니다. 입력창·선택창·편집기·터미널의 방향키는 해당 입력기가 처리합니다.
- 단추 묶음은 공용 `useRovingToolbar`를 사용하고, 폼 입력을 단추 선택자로 포함하지 않습니다. 선택 이동만으로 Git 쓰기 작업을 실행하지 않습니다.
- 문서에 도구 모음을 추가할 때 `⌘2` 등 영역 포커스 명령이 본문 대신 단추를 선택하지 않는지 확인합니다. 목록·트리 본문은 `data-primary-focus`, 편집기는 CodeMirror 본문을 우선합니다.
- 검색은 조합 중인 한글 Enter를 열기 명령으로 처리하지 않습니다. 결과가 없을 때 커서 인덱스를 음수로 누적하지 않고, 활성 결과를 스크롤과 접근성 정보로 함께 알립니다.
- 메뉴·검색·팝오버를 닫으면 출발한 컨트롤로 복귀합니다. 사라진 요소와 숨은 영역에 포커스를 두지 않습니다. 편집기의 Tab 들여쓰기와 Esc 다음 Tab으로 빠져나오는 동작을 유지합니다.
- 변경 파일의 다음/이전 탐색은 같은 저장소·같은 Staged/변경 영역에 한정합니다. 커밋·범위·스태시는 열 당시 OID와 파일 목록을 유지합니다.
- 변경 탐색은 현재 파일 경계에서 이웃 파일의 첫/마지막 변경으로 이어집니다. 별도의 파일 이동도 제공합니다. 전체 파일 목록 끝에서 순환하지 않습니다.
- 접힌 디렉터리의 파일로 이동하면 그 파일의 조상을 펼치고 선택 항목을 보이게 합니다. 파일 목록과 diff의 선택 표시가 달라지지 않도록 합니다.
- 파일 이동은 현재 diff 탭을 재사용합니다. 이미 열린 목적 탭이 있으면 활성화하고, 독립 문서의 ID와 파일 내용이 어긋나지 않게 합니다.
- 잘린 diff, 바이너리, 변경 없음, 조회 실패는 서로 다른 상태로 표시합니다. 표시하지 않은 변경을 본 것으로 취급하거나 오류 파일을 자동으로 건너뛰지 않습니다.

## 9. F7 연속 탐색과 가로 스크롤 보완

파일 경로와 원문이 다른 중간 렌더에서는 도착 포커스 요청을 소비하지 않습니다. 파일 전환·자동 갱신 중에는 소유했던 포커스를 diff 컨테이너에 남기고 새 본문으로 이어 줍니다. 사용자가 다른 컨트롤로 이동한 경우에는 포커스를 복구하지 않습니다.

Project·변경 파일·브랜치 트리는 가상 DOM 밖의 펼친 행까지 포함한 내용 폭으로 가로 스크롤을 제공합니다. 통합 로그 저장소 열은 폴더별 선호 폭을 저장하며 좁은 화면에서는 조절 경계가 남도록 표시 폭을 제한합니다.

- 수정 전 F7 재현 실패와 수정 후 반복·역방향·버튼 시작·자동 갱신·외부 포커스 보존 테스트를 확인했습니다.
- 표시된 macOS WebKit에서 실제 현재 포커스로 반복 F7 이벤트를 전달해 네 파일 연속 이동과 마지막 포커스 유지를 확인했습니다.
- Chromium에서 Project 200/434px, 브랜치 179/743px, 좁힌 변경 파일 목록 160/287px의 viewport/내용 폭을 확인했습니다. 가로 위치 150px·100px에서 방향키 이동 후 위치가 유지됐습니다.
- 전체 lint·타입 검사·테스트 202개 파일/2,373개와 배포 웹 빌드가 통과했습니다.

## 10. 기본 언어·한국어 문구·저장소 구분 색상

- 저장된 언어 설정이 없으면 영어로 시작합니다. 명시적으로 저장한 한국어·시스템 언어 선택은 유지하며 설정에서 변경합니다. UI 사전·날짜 포맷·HTML 언어의 초기값과 앱 셸 초기화 오류의 기본 언어도 영어입니다.
- 한국어 UI·네이티브 메시지의 커밋·브랜치·저장소·태그·스태시·병합·리베이스 용어와 안내 문장을 정리했습니다. 실제 Git 명령·옵션·설정 키·식별자·사용자 데이터는 번역하지 않습니다.
- 저장소 색상은 일반 브랜치 그래프의 10색과 분리합니다. 활성 폴더의 저장소 집합이 추가·삭제되면 전체 팔레트를 다시 배정하며 정렬·필터·스크롤은 색을 바꾸지 않습니다. 원본 저장소와 워크트리는 같은 common_dir 색상 슬롯을 공유합니다.
- `--repo-color-N`과 Canvas가 같은 팔레트를 사용합니다. 작은 집합은 색상군을 먼저 고르게 확보하고 실제 배경 혼합색의 OKLab 거리를 고려합니다. 일반 상태와 범위 선택 상태의 글자 대비는 4.5:1, 그래프 색 대비는 3:1 이상을 검사합니다.
- 색상 슬롯은 u16이며 IPC 숫자 형식은 유지합니다. 256개를 넘겨도 슬롯을 10색으로 나누지 않습니다. 많은 저장소에서는 색상만으로 구분하기 어려우므로 이름을 함께 표시합니다.
- 최종 프런트엔드 검사에서 206개 파일/2,394개 테스트, 배포 웹 빌드와 워크스페이스 Rust Clippy가 통과했습니다. 색상·테마·집합 변경, 300개 저장소 슬롯과 native graph/folder 회귀도 검사했습니다. 브라우저에서 영어 첫 실행, 한국어 선택·재실행 유지, 라이트/다크 팔레트를 확인했습니다.
